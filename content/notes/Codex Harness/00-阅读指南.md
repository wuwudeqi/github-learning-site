# Codex Harness

一个用户说“修好这个测试”，模型却不能凭空读取文件、启动进程或判断操作权限。谁把这些能力组织起来？任务持续几十轮后，谁维护状态、处理失败、把结果交给用户？这就是本专题研究的工程层。

学习主线是：**沿一次真实执行追踪对象、事件、状态与错误，再用受控实验验证判断。** 本版面向已经写过工具调用循环、了解基础 Agent 概念的读者。01 可快速浏览；重点从 02 的三层循环进入。Rust 语法按需补充，读到 Arc、Future、锁和取消时解释它们在此处的实际语义。

## 本版要真正读懂的六件事

1. 三层循环各自为什么继续：任务推进、请求重试、流事件消费。
2. StepContext 如何关联模型看到的能力与后续执行能力。
3. 工具已执行、响应已结束、结果已入历史为什么是三个时刻。
4. for_prompt 的结构修复、稳定合成 ID 与写时复制分别影响什么。
5. RwLock 准入与 FuturesOrdered 收集为什么是两套顺序规则。
6. 断流、取消、压缩时，哪些状态要保留，哪些身份与基线要重建。

## 开源范围

官方列出的开源组件包括 Codex CLI、SDK 和 App Server；IDE 扩展、Codex cloud 未开源。工程组件开源不能推导出模型权重开源。[官方开源清单](https://learn.chatgpt.com/docs/open-source)
