# 阅读指南：先把一次问答看清楚

员工已经能拉取代码，却不知道怎样申请生产发布权限；代码合并后没有触发流水线，他在几篇 Wiki 之间来回查，也没弄清应该先检查哪里。这套 RAG 的任务，是从内部研发平台资料中找到适用的依据，整理成能照着理解和操作的回答。

知识范围覆盖代码托管与 CI/CD 的功能说明、使用指引、权限申请、故障记录、版本变化和跨系统配置。故障排查只是其中一部分。

这份资料面向有 Java 后端经验、Python 刚入门的读者。每章先说明一个具体问题，再看输入输出与关键代码，最后解释怎样检验修改。管理后台、登录页面和复杂部署不在本轮学习主线里。

> 先挑一道“怎样申请仓库权限”的题，把原文、解析结果、chunk、候选、最终上下文和答案放在一起看。每一步都能对上，再尝试跨系统问题。

## 这套项目采用什么

Python 负责解析和检索代码，LangGraph 组织在线问答的状态与分支。向量部分采用 BGE 中文模型和 Qdrant 本地模式，关键词检索使用 BM25，再用 RRF 合并候选。重排与生成分别有独立接口，避免一个框架调用把内部过程全部藏起来。

| 部件 | 在项目里承担什么 | 学到哪一步 |
| --- | --- | --- |
| HTML / PDF 解析 | 提取正文并保留来源、章节或页码 | 能发现解析导致的证据缺失 |
| BGE Embedding | 将问题和片段编码到同一个向量空间 | 理解模型、前缀、长度和索引的一致性 |
| Qdrant local | 保存向量与元数据，执行相似检索 | 理解入库、查询、筛选与版本替换 |
| BM25 + RRF | 补充精确术语检索并融合结果 | 能算出一个候选为什么进入结果 |
| Reranker | 对已有候选按问题重新评分 | 区分召回损失与排序损失 |
| LangGraph | 管理节点、条件分支与一次补检索 | 能追踪状态，解释为什么继续或结束 |
| 评测代码 | 对照标注记录检索表现，保留回答评审清单 | 能报告局部改善及其代价 |

这些是教学选择，不表示每个企业都应使用相同组合。学习时先固定一套配置，再用实验决定换哪一部分。BGE 模型说明、LangGraph 文档和检索资料的引用放在对应章节，版本与运行命令以 [代码说明](code/README.txt)为准。

## 模拟资料与真实经历分开记录

[数据说明](data/DATASET.txt)记录了语料与题目的范围。[corpus.jsonl](data/corpus.jsonl)是编纂清单，[questions.jsonl](data/questions.jsonl)包含问题、参考答案、证据位置与禁止出现的错误结论。网页正文位于 `data/wiki/`。

CodeHub 和 FlowCI 在本套资料中是虚构的平台代称，申请入口使用 `example.invalid`。其中的角色名称、有效期和审批规则是为了测试而设定的规则，不是对某个真实产品的说明，也不是你所在公司的规定。

默认索引只读取知识文档。问题集里的参考答案和证据标注只进入评测，不能混入向量库。PDF 样本是部分 Wiki 的同源导出，用于观察解析差异，不能当成新增知识重复计算数量。

> [!WARNING] 一种容易把结果做漂亮的错误
> 如果把题目和参考答案也放进检索库，问题可能很容易命中自己的答案。这个分数无法说明系统能处理真正的新问题。

## 代码怎样读

需要本地运行时，先下载 [完整学习包](rag-learning-kit.zip)。解压后保留 `code/`、`data/` 与 `images/` 的相对位置，再按 [安装与运行说明](code/README.txt)操作。学习包包含全部正文、关键代码和模拟资料，不含模型权重或 API 密钥。

| 文件 | 先看什么 |
| --- | --- |
| [ingest.py](code/ingest.py) | 网页正文与 PDF 页文本怎样变成统一输入 |
| [chunking.py](code/chunking.py) | chunk 字段、长度预算与来源定位 |
| [retrieval.py](code/retrieval.py) | 问题向量、关键词候选、RRF 与重排接口 |
| [graph.py](code/graph.py) | 状态如何更新，路由为何选择某个分支 |
| [model_api.py](code/model_api.py) | 如何把真正的生成模型接到证据输入上 |
| [evaluate.py](code/evaluate.py) | 分母、证据命中、首个正确结果的位置 |
| [demo.py](code/demo.py) | 从输入问题到运行结果的最小入口 |

Python 的 `dataclass` 可以先类比 Java 的数据对象，`TypedDict` 用来描述字典字段，类型注解帮助读代码，但不自动完成所有运行时校验。节点函数返回部分字段，LangGraph 按状态定义应用更新；这和直接修改一个任意共享 Map 有区别，第 06 篇会具体展开。

正文代码分为“实际源码片段”和“解释某个机制的最小示意”。运行时以下载源码为准。替身回答只能验证流程，不能证明真实模型能够理解问题；真实向量检索的记录也不能直接当作回答准确率。

## 一次学习结束时留下什么

读完一章，至少能回答一个具体问题：哪段原文丢了？哪个条件筛错了？正确片段在第几名？改写是否改变了用户原意？返回的引用真的支持这条操作吗？

建议把笔记写成“现象、证据、修改、复测”的短记录。面试时挑两个有运行依据的案例展开，胜过把所有组件名称一起背出来。第 08、09 篇会把实验结果和可讲范围分开列明。
