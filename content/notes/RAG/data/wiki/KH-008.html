CodeHub 2.0：Webhook 配置、签名与投递记录

文档编号：KH-008；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

新建 Webhook

  1. 仓库维护者在“仓库设置 → 集成 → Webhook”新建订阅，填写经批准的 HTTPS 接收地址，按用途选择 push、merge_request 或 tag 事件。
  2. 连接 FlowCI 时，接收地址从 FlowCI 项目中的服务连接页复制，不手工猜测路径。
  3. 签名密钥由接收端与 CodeHub 配置一致，密钥不放在 URL 查询参数或普通日志中。
  4. 保存后发送一次测试事件，记录事件 ID 和接收端返回状态。

签名错误与订阅范围

接收端返回 SIGNATURE_MISMATCH 时，先核对两端引用的密钥版本，再检查接收端是否用原始请求体校验签名。先把 JSON 解析后重新序列化，可能改变字节内容而导致校验失败。此数据集不规定具体签名算法，不能据此拼造算法或请求头名称。没有投递记录时检查订阅事件是否包含当前操作；有记录但接收失败时再检查地址、签名和网络。测试事件成功只验证这一条测试请求。一次测试通过之后，仍需选取真实业务事件核对其订阅类型和接收结果。

重放和去重

CodeHub 对失败投递会记录尝试次数，维护者也可在“投递记录”中重放指定事件。重放保留原事件 ID。FlowCI 使用仓库 ID 与事件 ID 的组合识别重复通知，同一事件的重复投递不会创建第二个相同触发任务。不要把去重理解成所有相同提交都只能执行一次，人工重跑属于另一种操作。签名修复后只重放已确认失败的事件，并核对接收日志，避免无目的地批量重放历史记录。
