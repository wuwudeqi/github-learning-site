FlowCI 2.0：push、合并请求和标签触发规则

文档编号：KH-010；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

事件与分支规则

FlowCI 2.0 支持 push、merge_request、tag 和手动运行。push 规则匹配被推送的分支；merge_request 规则匹配合并请求的目标分支，不能把源分支当作目标分支填写。合并请求合入 main 后产生的 main 更新，需要由 main 的 push 规则承接后续构建。只配置 merge_request 的流水线不会因此自动变成 main 发布流水线。没有自动任务时先确认事件类型和规则匹配对象。源分支名称出现在日志中，不代表该规则按源分支匹配，需回到事件类型确认字段含义。

路径条件与跳过标记

路径过滤按该事件涉及的变更文件判断。只修改 docs/ 而规则只包含 src/ 时，事件可以投递成功但不会创建任务；在触发详情中查看“不匹配的路径规则”。提交信息包含 [skip flow] 时会跳过 push 自动构建，手动运行仍可发起，merge_request 和 tag 规则不受该标记影响。不要把界面没有任务直接归因于 Webhook 丢失，要先看是否有已接收但被规则过滤的事件。

标签发布与重复执行

tag 规则匹配标签名，例如 release-*；标签命名约定需要与流水线规则一致。创建合并请求、推送提交和创建标签可能分别触发任务，即使它们引用同一提交也不等于重复投递。需要避免双构建时，先约定分支与合并请求两种流水线的职责，再调整规则。人工重跑会生成新的运行 ID，并保留原提交和触发来源记录。排查时同时核对运行 ID、提交 SHA、事件类型，不能只比较分支名称。
