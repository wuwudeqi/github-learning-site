CodeHub 2.0：SSH 公钥登记与 Permission denied 排查

文档编号：KH-004；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

登记公钥并验证账号

SSH 适用于本机 Git 操作和已批准的自动化账号。个人在“账号设置 → SSH 公钥”登记公钥内容，备注设备用途并设置到期日，私钥保留在自己的设备上。复制时从公钥文件读取完整一行，不能上传私钥文件。完成登记后执行 ssh -T git@codehub.example.invalid ，返回当前账号名才能说明 SSH 身份验证通过。即使身份验证通过，也还需要具备目标仓库的访问权限。

出现 Permission denied (publickey)

克隆或推送时出现 Permission denied (publickey)，先执行 git remote -v 确认连接的是 codehub.example.invalid，再用 ssh -vT git@codehub.example.invalid 查看实际尝试的公钥指纹。将该指纹与账号设置中未过期的公钥核对。存在多个密钥时检查本机 SSH 配置中的 Host、IdentityFile 和 IdentitiesOnly，确认没有选到其他账号的密钥。排查时只分享指纹和脱敏日志，不发送私钥。错误仍存在时记录错误原文和时间，提交支持单。同一台设备上浏览器与命令行可能使用不同账号，比较身份时以命令行返回的账号为准，不只看网页头像。

认证通过但仓库仍不可访问

如果 ssh -T 返回了正确账号，而 git clone 提示 Repository not found，应检查克隆地址、项目路径是否变更，以及该账号在仓库成员页是否仍有读者或以上角色。这个提示可能掩盖私有仓库不存在或没有访问权限两种情况，不能单凭它判定仓库被删除。若只有推送 main 失败而克隆正常，转查分支保护和提交规则。流水线中的检出任务使用服务连接里的自动化身份，不会自动读取员工本机的 SSH 公钥。
