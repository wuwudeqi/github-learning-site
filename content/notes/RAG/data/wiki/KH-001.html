CodeHub 2.0：创建仓库与首次提交

文档编号：KH-001；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

创建前确认项目归属

本指引适用于 CodeHub 2.0。仓库必须放在已登记的项目空间中，不能创建在个人名下再用于团队交付。申请人准备项目编号、仓库英文短名、用途和代码负责人。代码负责人需要是该项目的正式员工。项目空间的维护者可以创建仓库；普通开发者先向维护者提交创建请求。仓库短名在同一空间内唯一，创建后修改短名会改变克隆地址，建议按服务名命名，避免包含环境或个人姓名。

创建与初始化步骤

  1. 打开 https://codehub.example.invalid/projects ，进入项目空间，选择“仓库 → 新建”。
  2. 填写仓库短名和用途，选择私有可见性，并确认代码负责人。
  3. 新项目勾选初始化 README，默认分支为 main；准备导入已有 Git 历史时不要初始化 README，先创建空仓库。
  4. 完成后记录仓库 ID。
  5. 使用仓库页给出的 SSH 或 HTTPS 地址提交，首次推送成功后检查默认分支和提交人信息，再由维护者配置 main 分支保护。

已有代码导入和交付检查

导入已有代码时，先检查原仓库是否含密钥、超大二进制文件或不应迁移的分支。确认目标是空仓库后再迁移所需分支和标签。仓库创建成功只表示代码托管位置已存在，不会自动创建 FlowCI 流水线，也不会授予任何环境的发布权限。交付给团队前，维护者应核对成员列表、默认分支、保护规则和克隆地址。若仓库短名已被占用，先确认是否已有同一服务的仓库，不要为了绕开重名反复创建副本。
