CodeHub 2.0：main 分支保护与推送限制

文档编号：KH-006；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

默认保护规则

新仓库完成初始化后，由维护者给 main 配置保护规则。团队交付仓库的批准模板要求禁止直接推送 main、禁止强制推送，并通过合并请求合入代码。开发者向自己的功能分支推送，评审通过后再合并。维护者角色负责配置规则，但在本模板下同样不通过直接推送绕过评审。临时放开规则需要项目负责人确认变更理由和恢复时间，不能把修改保护规则当成日常发布步骤。

合并条件与检查对象

在“仓库设置 → 分支保护”选择 main，关联评审规则和 FlowCI 状态检查名称 build/test。规则按目标分支生效；保护 main 并不自动保护 release/*，需要单独配置匹配规则。合并前系统检查的是当前合并请求最新提交 SHA 对应的 build/test 状态，其他分支或旧提交的绿色构建不能替代。新增提交后，需要等待该提交的状态回传。只有截图而没有对应提交记录，无法作为系统放行依据。

推送拒绝怎样判断

如果 git push 被拒绝并提示 protected branch，先检查当前分支和远端目标，不要反复刷新 SSH 公钥。克隆和功能分支推送均成功、只有 main 被拒绝，通常应按合并请求流程处理。若合并按钮提示状态检查未完成，则查看最新提交 SHA、流水线检查名称和回传结果。检查名称拼写或大小写不一致也会造成等待。需要紧急修复时仍保留评审和构建证据，按项目批准的应急流程申请处理。
