CodeHub 2.0：克隆失败的网络、认证与授权分层检查

文档编号：KH-018；适用版本：2.0；状态：active；资料类别：faq；审定级别：approved；更新日期：2026-08-20；环境：all

先保留错误原文

处理 git clone 失败时先记录完整错误、远端地址中的主机和路径、发生时间，以及使用 SSH 还是 HTTPS。分享日志前去掉令牌和个人敏感信息。Could not resolve host、连接超时、认证失败和 Repository not found 属于不同线索，不能都归为“没权限”。浏览器能打开门户首页也不能说明 Git 使用的主机、端口和网络路径都正常。先在同一台设备上复现，再比较其他设备的结果。当错误由其他同事转述时，先索取实际日志，避免把不同机器上的两次失败当作同一个现象。

网络层与认证层

Could not resolve host 时检查当前网络是否接入公司的批准访问通道，以及内部域名解析是否正常。连接超时则核对 Git 地址、网络连通性和服务公告；本资料没有列出真实内网地址、端口白名单或 VPN 配置，需向网络支持获取。SSH 的 Permission denied (publickey) 转查公钥指纹与实际账号；HTTPS 的 Authentication failed 转查访问令牌和缓存凭据。不要通过关闭证书校验来掩盖连接问题。

仓库路径与成员关系

认证已经成功而 Repository not found 时，核对仓库是否转移或改名，复制当前仓库页的克隆地址，并让代码负责人确认账号成员关系。该提示不能区分隐藏的私有仓库与不存在的仓库，不能直接宣布仓库被删除。只有 push main 被拒绝而 clone 正常时，检查分支保护。提交支持单时附错误原文、协议、仓库 ID、时间和已做的检查，避免只提供“拉不下来”这一句话。
