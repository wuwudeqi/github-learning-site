CodeHub 2.0：HTTPS 令牌与凭据更新

文档编号：KH-005；适用版本：2.0；状态：active；资料类别：guide；审定级别：approved；更新日期：2026-08-20；环境：all

令牌与账号权限的关系

CodeHub 2.0 的 Git HTTPS 操作使用个人访问令牌，网页登录密码不能用于 git clone 或 git push。令牌绑定创建它的账号，只能在该账号已有的仓库权限内工作。只拉取代码时选择 repo:read；需要推送开发分支时选择 repo:write。令牌权限范围不会绕开分支保护，也不会授予仓库成员关系。自动化任务应使用经过批准的服务账号令牌，避免员工离职后影响长期运行的任务。

创建令牌和本机更新

在“账号设置 → 访问令牌”创建令牌，写明用途，选择最小权限范围和到期日。令牌明文只在创建时显示一次，应保存到批准的凭据管理工具。Git 提示用户名时填写 CodeHub 账号，密码位置填令牌，不要把令牌拼进仓库 URL。更换令牌后，如果本机仍提示 Authentication failed，先清理凭据管理器里该主机的旧凭据，再重新输入；浏览器能正常登录不能证明本机 Git 正在使用新令牌。

失效、泄露与流水线配置

排查 401 时检查令牌是否到期、撤销或仍在使用旧值；403 还需检查账号的仓库角色和令牌范围。不能仅凭状态码认定唯一原因。怀疑令牌泄露时立即撤销并创建替代令牌，同时核对相关访问记录。流水线应在 FlowCI 服务连接中更新凭据，修改本机凭据不会影响执行器。更新后先用只读检出任务验证，再检查需要写权限的操作，不要为排查方便把令牌权限扩大到全部仓库。
