故障记录：合并完成但 main 流水线没有运行

文档编号：KH-017；适用版本：2.0；状态：active；资料类别：incident；审定级别：case_record；更新日期：2026-08-28；环境：all

现象与本次结论

模拟事件 INC-2026-017 发生在 FlowCI 2.0 与 CodeHub 2.0 的示例项目。合并请求评审通过并已合入 main，开发者没有看到预期的 main 构建。本次最终发现流水线只配置了 merge_request 事件，没有配置 main 的 push 规则。这是一次案例结论，不能据此判断所有“合并后没构建”都由同一原因引起。排查时需要拿到仓库 ID、合并后的提交 SHA、预期流水线 ID 和发生时间。

沿事件链逐步定位

先在 CodeHub 核对 main 上确实存在目标提交，再查该次 push 的 Webhook 投递记录和事件 ID。接收端已确认收到事件后，转查 FlowCI 触发详情的过滤原因。本次触发详情显示 EVENT_RULE_MISMATCH，进一步核对配置后确认缺少 main 的 push 规则。若没有接收记录，应继续检查订阅、投递地址和签名；若记录显示路径过滤或跳过标记，应按对应原因处理，不能继续套用本次结论。分段检查时保留每一步的记录，已经证实成功的环节无需反复配置。若缺少原始投递记录，就应保留结论的不确定性。

处理与验证记录

维护者补充 main 的 push 规则，提交配置变更，先用专门的验证提交确认目标任务创建，再核对运行 ID 和提交 SHA。对之前未运行的目标提交，经项目负责人确认后手动发起构建，保留其原始提交记录。本次没有重新合并已经合入的代码，也没有关闭签名校验。修复后检查 merge_request 构建与 main 构建是否按各自用途触发，避免补规则后出现未经预期的双构建。
