# 模型怎样从文本中学习

上一章的小模型能输出概率，却会写出“小猫饿了它小猫”。网络会计算，不代表参数已经有用。现在回到第 01 章的训练循环，把“打印费用”换成“下一个 Token”：

```text
准备前缀和目标 → 计算候选分数 → 计算损失
              → 求梯度 → 更新参数 → 重新检查
```

本章会算完一次分类输出层的更新，并解释梯度怎样继续传向注意力和 Embedding。配套实验只实现输出层更新与数值核对，没有实现整个 Transformer 的反向传播，不能把它称为一次完整的语言预训练。

## 1. 一段文本怎样变成五道训练题

词表沿用第 02 章：

```text
小猫=0，饿了=1，它=2，吃=3，鱼=4，<结束>=5
```

准备文本“小猫饿了它吃鱼”，末尾加上教学结束标记，得到：

```text
完整序列：[0, 1, 2, 3, 4, 5]
输入 x： [0, 1, 2, 3, 4]
目标 y： [1, 2, 3, 4, 5]
```

输入去掉最后一项，目标去掉第一项，刚好错开一位。用文字对齐更容易检查：

| 输出位置 | 该行允许利用的输入前缀 | 该行要预测的目标 |
| ---: | --- | --- |
| 0 | 小猫 | 饿了 |
| 1 | 小猫 饿了 | 它 |
| 2 | 小猫 饿了 它 | 吃 |
| 3 | 小猫 饿了 它 吃 | 鱼 |
| 4 | 小猫 饿了 它 吃 鱼 | 结束 |

第 2 行的输入里有“它”，目标是“吃”。如果错把目标也写成“它”，任务就变成复制当前位置，训练损失可能很好看，却没有在训练我们需要的下一项预测。

很多文本都能这样自动产生目标，因此常称为自监督学习：监督信号来自数据自身，不代表没有目标或没有损失。

## 2. 训练能同时算多行，为什么没有偷看答案

完整训练文本已经给出，所以输入的五行向量可以一起进入矩阵计算；因果遮罩确保第 i 行仍只能使用 `0…i` 的输入。

训练时在前缀里提供数据中的真实历史，这种方式通常称为 teacher forcing。例如算“吃”之后的“鱼”时，输入使用训练文本里真实的“吃”，不必先等待模型自己成功生成“吃”。

“可以同时算”与“可以看到未来”是两回事：

- 能同时组织运算，是因为各位置输入已知。
- 哪些位置能彼此提供信息，由因果遮罩限制。
- 多个网络层仍有先后依赖，不能因此说整个网络没有顺序。

推理时未来 Token 尚未选出，所以通常需要逐步生成。本书脚本用 Python 循环逐行计算，便于阅读；数学上的批量组织与硬件并行并不要求每行都写成一个 Python 循环。

真实训练库可能在模型内部完成标签错位，也可能要求调用者自行处理。不能既手动错开一次，又让内部再错开一次。无论接口怎样设计，都应回到上面的表检查：**这一行的 logits 到底在预测哪一个目标？** [Hugging Face 因果语言建模教程](https://huggingface.co/docs/transformers/en/tasks/language_modeling)

## 3. 为什么语言模型不直接对 Token 编号算平方误差

打印费用有数值距离：预测 5 元比预测 100 元更接近目标 4 元。Token 编号没有这种含义。如果“鱼”的编号是 4，“吃”的编号是 3，不能说输出编号 3.9 就“几乎是鱼”。

我们把每个词表项看成一个类别，评价模型分给目标类别的概率。若真实目标为 y，最简单的单个位置交叉熵是：

```text
L = -ln(p_y)
```

ln 是自然对数。目标概率越大，损失越小：

| 分给目标的概率 | −ln(概率) |
| ---: | ---: |
| 0.80 | 0.223144 |
| 0.50 | 0.693147 |
| 0.25 | 1.386294 |
| 0.01 | 4.605170 |

把目标写成 one-hot 分布 y，也可以写为 `L=-sum(y_j×ln(p_j))`。只有目标那一项的 y 为 1，其余为 0，所以就剩下前面的 `-ln(p_y)`。

一条序列通常对需要训练的有效位置取平均。padding 是组织批量时补出来的，不应作为真实后续参与这种损失；其注意力可见性也需要另外处理。**损失遮罩控制哪些预测参与评分，注意力遮罩控制输入信息怎样流动，二者不能混用。**

### 3.1 接口里为什么常直接传 logits

如果先把极小概率算出来，再取对数，可能遇到下溢。把 Softmax 代入损失，可改写为：

```text
L = ln(sum(exp(z_j))) - z_target
```

再用减最大值的方法稳定地计算。这是脚本 `cross_entropy` 的做法。PyTorch 的 `CrossEntropyLoss` 同样接收未归一化 logits；使用它时不应先对 logits 做一遍 Softmax 再作为同样的输入传进去。[PyTorch 交叉熵接口](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)

## 4. 一次输出层训练：从分数算到新参数

为了将每个数字写出来，本节切换到一个独立的三候选分类例子，候选顺序为 `[鱼,猫粮,球]`。它不属于前面的六项教学词表。假设某个前缀的训练目标是“猫粮”，前面的网络已经给出表示 `h=[1,2]`。

暂时固定 h，只训练输出矩阵：

```text
         鱼      猫粮   球
W = [ ln(2),      0,    0 ]
    [    0,       0,    0 ]

z = h @ W = [ln(2),0,0]
p = softmax(z) = [0.5,0.25,0.25]
目标 one-hot：  y = [0,1,0]
旧损失：L = -ln(0.25) = 1.386294
```

这个矩阵两行、三列：h 有两维，候选有三类。每一列决定一个候选分数。

### 4.1 先求损失对三个分数的梯度

由上一节的式子：

```text
L = ln(exp(z_0)+exp(z_1)+exp(z_2)) - z_target
```

对 z_j 求导，前半部分得到 `exp(z_j)/sum(exp(z))`，就是 p_j；后半部分在 j 是目标时贡献 −1，否则为 0。因此：

```text
dL/dz = p-y = [0.5, -0.75, 0.25]
```

若把 z 本身当作可调量，沿负梯度走，会降低非目标分数、提高目标分数。实际模型要修改的是 W，因此还需要沿乘法回传一步。

### 4.2 再把梯度传回 W 的每个元素

第 j 个候选分数是：

```text
z_j = h_0×W_0j + h_1×W_1j
```

对 W_ij 而言，沿途还有一个乘数 h_i，于是：

```text
dL/dW_ij = h_i × (p_j-y_j)

h=[1,2]，所以：
dL/dW = [ 0.50, -0.75, 0.25 ]
        [ 1.00, -1.50, 0.50 ]
```

第二行是第一行的两倍，因为 h 的第二维为 2。这与打印店 `dL/dw=2e×x` 的逻辑相同：输出处的误差信号，还要乘上该参数影响输出的变化率。

### 4.3 更新并重新算一次

学习率取 0.1，使用旧参数处的全部梯度一起更新：

```text
W_new = W - 0.1×dL/dW

      = [ ln(2)-0.05, 0.075, -0.025 ]
        [   -0.10,   0.150, -0.050 ]

z_new = [0.443147, 0.375000, -0.125000]
p_new ≈ [0.399888, 0.373545,  0.226567]
L_new = -ln(0.373545) ≈ 0.984717
```

“猫粮”的概率由 0.25 提高到约 0.373545，损失下降了。但是最高概率仍是“鱼”！因此，这次更新改善了目标概率，**还没有让贪心答案变正确**。

这是一条有用的区分：损失是连续的评分，最高分是否选对是另一项指标。它们相关，但不保证每次更新都同时变化。

## 5. 梯度怎样继续传到注意力和 Embedding

刚才固定了 h。如果连前面的网络也训练，输出层还会给 h 传回梯度：

```text
dL/dh = (p-y) @ Wᵀ
```

在本节旧参数处，结果为 `[0.5×ln(2),0]`，约 `[0.346574,0]`。这表明当前损失也受到 h 的影响；我们可以继续沿 h 的计算过程求导。

完整路径可以展开为：

```text
损失
 ↓ 对候选分数的梯度
输出矩阵，以及最后的隐藏表示
 ↓
归一化、残差、前馈网络
 ↓
注意力中的加权和、Softmax、Q/K/V 投影
 ↓
更早的网络层与输入 Embedding
```

反向传播在每一步使用对应的局部导数，遇到残差等多条路径时累加贡献。Q、K、V 不是被永久存下的独立训练参数；梯度要继续传给生成它们的 W_Q、W_K、W_V，以及这些投影的输入。

同一个参数参与多个位置、多个样本的计算，其梯度贡献会相加；若损失取平均，也要有对应的平均系数。不能为每个位置更新一次后，再声称它们都使用了同一组旧参数。

本书没有手写这些模块的全部反向函数。实际训练框架可以通过自动求导组织这条计算图；你仍应能说明目标怎么对齐、哪些参数参与更新，以及梯度是否经过了期望路径。

## 6. 运行实验，用另一种算法检查梯度

在专题目录运行：

```bash
python3 code/transformer_lab.py loss
python3 code/transformer_lab.py check
```

[脚本下载](code/transformer_lab.py)。`loss` 会复现本章的三分类手算，最后打印：

```text
损失：1.386294 → 0.984717
```

`check` 还对第 04 章四维网络的输出层做独立验证：用前缀“小猫饿了它”，以“吃”为目标，固定前面的表示，对 `(4,6)` 矩阵的 24 个参数逐个检查。

解析计算使用刚才的 `h_i×(p_j-y_j)`；另一边不调用这条公式，而是微调参数后观察损失：

```text
数值梯度 ≈ [L(W_ij+ε) - L(W_ij-ε)] / (2ε)
ε = 0.000001
```

每次只改一个元素，其他参数固定，算完恢复原值。本次运行解析梯度与数值梯度的最大误差约为 `1.90×10^-10`，小于检查阈值 `10^-7`。随后更新输出矩阵，并确认该样本的损失下降。

这验证了输出层求导与更新；注意力的验证则来自前几章的手算、因果性和缓存一致性检查。不要把这些检查扩展解释成“整个网络的反向传播已经测试通过”或“模型有了可靠的语言能力”。

## 7. 从文本预训练到助手回答，中间改变什么

**文本预训练**可以大量使用文本中自动构造的下一项预测。模型在许多样本上共同调整参数，学习有助于预测文本的模式。

**监督微调（SFT）**可以改用任务输入与示范回答。例如：

```text
用户：把“小猫饿了”翻译成英文。
助手：The kitten is hungry.
```

训练仍可用 Token 级交叉熵，但数据组织、对话模板、哪些位置计入损失需要明确。若目标是训练助手回答，可以让用户消息作为条件，只对助手回答部分计入目标损失。系统仍需允许回答位置利用前面的用户输入，不能因为用户文字不计入损失，就把它从注意力里也遮掉。[Hugging Face SFT 训练说明](https://huggingface.co/docs/trl/en/sft_trainer)

有些后续训练还会利用偏好或奖励信号。这些方法涉及另外的目标与优化设计，本章没有用一个“打分后学习”的标签代替它们的实现。

“Transformer”说的是一类网络结构；“预测下一个 Token”说的是训练任务；“能按指令回答”还取决于数据与训练安排。这三层需要连起来理解。

## 8. 四个实际问题，应该怎样定位

### 8.1 为什么训练损失很低，换个问题却不会了

先判断评价输入是否参与过训练，以及新问题与训练分布有什么差异。只在“小猫吃鱼”上反复降低损失，不能证明模型能处理“小狗找球”，更不能证明它能做任意推理。

第 01 章只有一张打印订单时，许多规则都能得满分。语言模型参数更多，这种“当前数据拟合得好，但没有证明新任务也好”的问题仍然存在。

### 8.2 为什么句子流畅，里面的事实仍可能错

本章的损失直接评价训练目标的预测概率，没有在每次生成时自动查询事实来源。训练可以学到很多知识，但流畅程度和证据充分程度仍需要分别检查。对依赖资料的问题，应查看输入中的来源及模型是否忠实使用它们。

### 8.3 检索增强与微调有什么区别

假设要回答公司新发布的报销规则：检索可以把相关条文选出来，作为本次输入；微调则通过训练修改参数。这两种动作发生在不同位置，也可以组合使用。

| 动作 | 主要改变 | 回答前应检查什么 |
| --- | --- | --- |
| 提示词补充说明 | 当前输入 | 说明是否完整、是否进入上下文 |
| 检索并附上条文 | 当前输入中的资料 | 是否找对版本、片段是否覆盖问题 |
| 微调 | 参与训练的参数 | 数据、目标、留出评估是否合适 |
| 调整温度 | 选词分布 | 选择策略是否适合任务，不能据此证明事实正确 |

不要把“模型没看到最新条文”直接归结为“参数量不够”，也不要把所有回答问题都当成需要训练。先追踪信息在哪一步缺失或使用错误。

### 8.4 在对话里纠正一次，算不算训练

普通生成可以把纠正内容作为新上下文，因此接下来回答得更好；这本身没有证明优化器更新了参数。产品是否另行保存记录、是否安排后续训练，属于独立流程，不能从一次回答变化推出。

## 9. 换条件练习与解答

**题一：** 文本编号为 `[2,3,4,5]`，用错开一位的方法写出输入与目标。

**解答：** 输入 `[2,3,4]`，目标 `[3,4,5]`。第二个输入位置是“吃”，该行的目标是“鱼”，不是“吃”。

**题二：** 模型给目标的概率从 0.25 变成 0.50，交叉熵降低多少？

**解答：** 从 `ln(4)` 降到 `ln(2)`，减少 `ln(2)≈0.693147`。这并没有说明其他样本的损失也下降，仍需分别评价。

**题三：** 三候选概率仍是 `[0.5,0.25,0.25]`，但训练目标改成“鱼”，dL/dz 是多少？

**解答：** 目标 one-hot 变成 `[1,0,0]`，所以梯度为 `[-0.5,0.25,0.25]`。同一个预测配上不同目标，产生不同训练信号；目标来自样本，不是模型自己随意指定。

**题四：** 某位置不参与损失，它是否一定不能影响其他位置的训练？

**解答：** 不一定。它仍可能通过注意力作为其他位置的信息来源，从其他目标损失接收到梯度。忽略该位置的目标评分，与切断它的信息路径不同。

**题五：** 本章更新后目标概率提高，最高分仍然错误，是否说明梯度一定算错？

**解答：** 不是。损失从 1.386294 降到 0.984717，但 0.373545 仍小于“鱼”的 0.399888。连续评分已改善，却还没有跨过类别排序的边界。

**题六：** 只训练输出层可以验证哪些事，不能验证哪些事？

**解答：** 可以验证给定表示上的分类损失、输出矩阵梯度和更新；不能验证注意力及 Embedding 的反向实现，也不能用一个样本的改善证明泛化或完整预训练效果。

## 10. 把六章串成一次完整解释

现在回到“小猫饿了它”：先切分编号、查 Embedding、加入位置；每层把 Q 与允许的 K 匹配，再按权重汇入 V；残差、归一化与前馈网络继续变换表示；输出层给各个词表项打分；生成程序选一个 Token 加入前缀，并利用缓存减少重复计算。

训练时，数据提供真实后续，错开一位形成目标，交叉熵评价目标概率，反向传播把影响传回参数，优化器按规则更新。推理则在已有参数上继续计算，两者共享前向网络，却不是同一个循环。

试着不看正文画出这条路径，在每个箭头旁写出一个本书算过的数或形状。如果某一步只能写“模型理解了”，就回到对应章节，把它替换成明确的输入、运算与输出。
