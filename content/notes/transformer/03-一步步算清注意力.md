# 一步步算清注意力

上一章，“小猫”“饿了”“它”各自领到了一行向量。现在轮到“它”干活，可它手里只有刚查到的几个数：前面是谁、发生了什么，都还没汇进来。我们得给这个位置接上前文的信息。

最省事的办法是求平均，大家一人一票。可前文一长，每个位置永远分到同样的比例，就没法根据当前输入调整“多取谁、少取谁”。注意力于是多做一步：**先根据输入算出每个来源的权重，再把信息按这个比例组合起来。**

为了能亲手算到底，这一章暂时把向量缩成二维，单独看注意力。参数与上一章的四维表分开，也先不加位置编码、归一化和残差。咱们先把一个零件拆明白，下一章再把整台小机器装起来。

## 1. 先说清三个动作，再命名 Q、K、V

先借一个查书的场景：你拿着“想找 Python 入门材料”的需求，用书的索引信息筛选，最后取回书中的内容。这里有三份不同的东西：拿什么去找、靠什么匹配、最后取回什么。注意力也把这三项分开计算。

注意力把这三个用途分别放进三组向量：

| 名称 | 本次计算中的作用 | 常见记号 |
| --- | --- | --- |
| Query，查询 | 当前这行拿什么去匹配来源 | Q |
| Key，键 | 各个来源拿什么接受匹配 | K |
| Value，值 | 匹配权重确定后，要汇入什么信息 | V |

查书只是帮助理解分工。真正运行时，没有一位图书管理员在模型里翻书，只有矩阵乘法、点积和加权和。Q 是向量，不是一句汉语问题；K 也不一定能直接读成关键词。

本例每行代表一个位置，采用：

```text
             第 1 维  第 2 维
X = 小猫 [      1,       0 ]
    饿了 [      0,       1 ]
    它   [      1,       1 ]
```

选择三组简单参数：

```text
W_Q = [1, 0]    W_K = [1, 0]    W_V = [1, 0]
      [0, 1]          [0, 1]          [0, 2]

Q = X @ W_Q
K = X @ W_K
V = X @ W_V
```

W_Q、W_K 是单位矩阵，因此 Q、K 保持原值。W_V 把第二维乘 2：

```text
Q = K = [1, 0]      V = [1, 0]
        [0, 1]          [0, 2]
        [1, 1]          [1, 2]
```

以 V 的最后一行为例：

```text
[1,1] @ W_V = [1×1+1×0, 1×0+1×2] = [1,2]
```

这里 W 是人为设定的；真实网络通常通过训练学习这些矩阵。**W_Q、W_K、W_V 是参数；Q、K、V 是输入经过参数计算出来的中间结果。** 换一句输入，参数可以不变，中间结果会改变。

## 2. 让每个 Query 与每个 Key 打一次分

取“它”的 Query `[1,1]`，分别与三个 Key 做点积：

```text
对“小猫”： [1,1]·[1,0] = 1
对“饿了”： [1,1]·[0,1] = 1
对“它”：   [1,1]·[1,1] = 2
```

它对三个来源的原始分数是 `[1,1,2]`。三个 Query 都做一遍，就得到：

```text
Q @ Kᵀ = [1, 0, 1]
         [0, 1, 1]
         [1, 1, 2]
```

Kᵀ 表示把 K 的行列交换。Q 是 `(3,2)`，Kᵀ 是 `(2,3)`，乘起来得到 `(3,3)`。这个结果中：

- 行表示“哪个位置在查询”。
- 列表示“被查询的是哪个来源位置”。
- 第 i 行、第 j 列是 Query_i 与 Key_j 的匹配分数。

先别把 2 读成“200% 的注意力”。这会儿只有原始分数，它可以大于 1，也可以为负。概率和最终输出还在后面的工序里。

## 3. 缩放和遮罩，分别在解决什么问题

### 3.1 先按 Key 的宽度缩放

缩放点积注意力把分数除以 `sqrt(d_k)`。本例 Key 有两维，所以除以 √2：

```text
S = [0.707107, 0,        0.707107]
    [0,        0.707107, 0.707107]
    [0.707107, 0.707107, 1.414214]
```

为什么需要缩放？在一个用于分析的简化假设下：Q、K 的各分量独立、均值为 0、方差为 1，那么 d_k 个乘积相加的方差约为 d_k，典型波动规模随 √d_k 增长。直接送进指数函数，分数差异可能被放大，使 Softmax 过早集中在少数位置。

除以 √d_k 是控制尺度的设计。这段分析依赖上述假设，不表示所有训练后的分量都严格满足它，也不保证缩放后每个分数都落在 0 到 1 之间。[原始 Transformer 论文，第 3.2.1 节](https://arxiv.org/html/1706.03762v7)

### 3.2 为什么必须遮住未来

我们练的是“看前缀，猜下一项”。第一个位置“小猫”要预测“饿了”，若把第二个位置直接给它看，就相当于把答案页摊在桌上，再夸它考得好。分数也许漂亮，任务已经变味了。

因此第 i 个位置只能使用位置 `0…i`，包括自己，不能使用 `i+1` 及之后的位置。这个规则叫**因果遮罩**。

```text
              来源 0   来源 1   来源 2
查询位置 0：    允许     禁止     禁止
查询位置 1：    允许     允许     禁止
查询位置 2：    允许     允许     允许
```

用加法遮罩 M 表示：允许处加 0，禁止处加负无穷。

```text
M = [0, -∞, -∞]
    [0,  0, -∞]
    [0,  0,  0]

S + M = [0.707107, -∞,       -∞]
        [0,        0.707107, -∞]
        [0.707107, 0.707107, 1.414214]
```

下一步取指数，`exp(-∞)=0`，未来位置才真正分不到权重。答案页这才算盖严了。

**把禁止处乘成 0，不也清零了吗？** 别忘了下一站是指数函数：`exp(0)=1`，刚刚归零的分数又会分到权重。先做 Softmax、再抹掉未来权重也不能就此收工，因为剩下的权重通常不再加起来等于 1。遮罩要放对位置，顺序不能凭感觉调。

配套代码采用等价的简单做法：每次只把允许的 K、V 前缀传入计算。这样无需在 Python 中构造负无穷矩阵。本例每行至少能看到自己，不会出现整行都被屏蔽的情况。

## 4. 用 Softmax 算出真正的组合比例

对每一行分别取指数、除以该行指数之和。第三行可以完整算成：

```text
缩放分数： [0.707107, 0.707107, 1.414214]
取指数：   [2.028115, 2.028115, 4.113250]
总和：      8.169480
权重：     [0.248255, 0.248255, 0.503490]
```

第一行只有一个允许来源，权重为 `[1,0,0]`。第二行的有效分数是 `[0,0.707107]`，得到 `[0.330238,0.669762,0]`。因此整张注意力权重矩阵为：

| 查询位置＼来源 | 小猫 | 饿了 | 它 |
| --- | ---: | ---: | ---: |
| 小猫 | 1.000000 | 0 | 0 |
| 饿了 | 0.330238 | 0.669762 | 0 |
| 它 | 0.248255 | 0.248255 | 0.503490 |

每行一共只有 1 份权重，三个来源按比例分。本例“它”给自身分得最多，是我们选的向量算出来的结果。别急着宣布它找到了“小猫”这个指代对象：第三行表示信息怎样混合，不能读成“它有 24.8% 的概率是小猫”。

### 4.1 为什么不直接除以分数之和

如果分数是 `[-1,1]`，和为 0，根本无法这样除；其他情况下还可能得到负权重。指数把有限分数映射成正值，再归一化，得到可用于组合的比例。

计算机还要考虑数值范围。`exp(1000)` 会溢出，因此实际实现通常先减去本行最大值：

```text
softmax([1000,1001]) = softmax([-1,0])
```

每项的分子分母同时消去同一个因子，概率不变。这既是代数性质，也能变成检查程序是否正确的一条测试。

## 5. 权重算完以后，到底取回了什么

权重乘的是 V，不是候选词表。第三个位置的输出为：

```text
输出 = 0.248255 × [1,0]
     + 0.248255 × [0,2]
     + 0.503490 × [1,2]

第 1 维 = 0.248255 + 0 + 0.503490 = 0.751745
第 2 维 = 0 + 0.496510 + 1.006980 = 1.503490
```

三行一起写成 `A @ V`：

```text
[1.000000, 0.000000]
[0.330238, 1.339523]
[0.751745, 1.503490]
```

结果仍是三行二维向量。算了这么一大圈，“吃”与“鱼”还没出场，因为注意力的工作是更新表示。信息组合好了，接下来还得经过网络的其他部分和输出层，才能给候选 Token 打分。

到这里才适合把整段过程缩写成一个公式：

```text
Attention(Q,K,V) = softmax(Q @ Kᵀ / sqrt(d_k) + M) @ V
                       沿每一行归一化
```

读公式时按我们刚才的顺序展开：匹配、缩放、限制可见位置、计算比例、组合内容。

## 6. 为什么分成三套矩阵，又为什么使用多头

### 6.1 K 和 V 都来自 X，为什么还要分开

匹配依据与取回内容可以不同。本例 V 将第二维加倍，Q、K 却没有加倍。如果只把 W_V 的右下角从 2 改成 4，注意力权重保持不变，输出的第二维会翻倍：

```text
原来最后输出：[0.751745, 1.503490]
修改后输出：  [0.751745, 3.006980]
```

现在看出 K 和 V 分家的用处了：匹配依据没动，取回的内容可以单独改。若直接让 Q=K=V=X，也算得起来，只是三种工作被绑在同一份表示上，网络能独立学习的变换就少了。

不同的 W_Q、W_K 还允许不对称匹配。“位置 A 如何查询 B”不必等于“位置 B 如何查询 A”。本章未遮罩的分数矩阵恰好对称，是因为特意取了 W_Q=W_K，不能据此推断所有注意力矩阵都对称。

### 6.2 多头不是把同一张权重表复制几次

设表示宽度 d_model=4，使用两个头，每头宽度为 2。每个头都通过自己的投影得到 Q、K、V，各自算出一份权重与输出：

```text
头 1 输出：(T,2)
头 2 输出：(T,2)
      ↓ 按特征列拼接
组合输出：(T,4)
      ↓ 乘 W_O，形状 (4,4)
注意力子层输出：(T,4)
```

例如同一个位置的两个头分别输出 `[1,2]`、`[3,4]`，拼接后是 `[1,2,3,4]`，不是 `[4,6]`；之后 W_O 可以重新混合各头的信息。

多头让网络同时学多组匹配与组合。不过我们没给各个头发“语法科”“指代科”的工作证；某个头究竟学到什么，得看实际证据。下一章的小网络先保留一个头，方便把每一步都算清。

## 7. 几个经常被混在一起的关联问题

**注意力分数就是余弦相似度吗？** 不是。点积也受向量长度影响。`[1,0]` 与 `[2,0]` 的余弦相似度为 1，点积却是 2；与 `[1,0]` 自身的点积为 1。本章没有先把 Q、K 归一化成单位长度，不能把点积直接称为余弦相似度。

**注意力权重和词表概率有什么不同？** 本章一行有 T 个权重，对应 T 个来源位置，用于混合信息；输出层一行有词表大小那么多个概率，用于预测下一类 Token。它们可能都用 Softmax，但归一化的对象不同。

**Self-attention 的“self”是不是只能看自己？** 不是。它表示 Q、K、V 来自同一条输入序列的表示。是否可以看后面，由遮罩决定。

**双向注意力与交叉注意力是什么？** 双向自注意力可以让一个位置利用同一序列两侧的有效位置，适合整个输入已经给出的编码任务。交叉注意力的 Q 来自一组表示，K、V 来自另一组，例如翻译解码器查询编码后的源句。生成目标文本时，目标侧的因果约束仍需正确处理。

## 8. 三个小实验，检查注意力有没有偷看答案

把下面整段保存成 `main.py`，执行 `python3 main.py`。Q、K、V 的构造、Softmax、加权和与三个对比实验都在这段代码里，不需要从别处导入函数。

先看 `attention_example` 中的 `end = i + 1`：这个边界决定每个位置能看见谁。遮罩的名字听起来像设备，落实到这里，就是别把不该看的那几行传进去。

```python
import math


def dot(a, b):
    if len(a) != len(b):
        raise ValueError("点积的两个向量必须等长")
    return sum(x * y for x, y in zip(a, b))


def linear(row, weights):
    return [dot(row, col) for col in zip(*weights)]


def softmax(scores):
    maximum = max(scores)
    # 减最大值不改变概率，可以避免 exp(1000) 这样的溢出。
    terms = [math.exp(s - maximum) for s in scores]
    total = sum(terms)
    return [t / total for t in terms]


def attend(query, keys, values):
    scores = [dot(query, key) / math.sqrt(len(query)) for key in keys]
    weights = softmax(scores)
    mixed = [sum(w * row[c] for w, row in zip(weights, values)) for c in range(len(values[0]))]
    return mixed, weights


def attention_example(causal=True, inputs=None, value_scale=2.0):
    x = inputs if inputs is not None else [[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]]
    # Wq=Wk=I；Wv=diag(1, 2)。这里不加位置编码、归一化或残差。
    q, k = x, x
    v = [linear(row, [[1.0, 0.0], [0.0, value_scale]]) for row in x]
    outputs, rows = [], []
    for i, query in enumerate(q):
        end = i + 1 if causal else len(x)
        output, weights = attend(query, k[:end], v[:end])
        outputs.append(output)
        rows.append(weights + [0.0] * (len(x) - end))
    return outputs, rows


def fmt(row):
    return "[" + ", ".join(f"{x:.6f}" for x in row) + "]"


def demo_attention():
    output, weights = attention_example()
    print("二维手算实验：因果注意力矩阵 A")
    for row in weights:
        print(fmt(row))
    print("A @ V：")
    for row in output:
        print(fmt(row))
    unmasked, _ = attention_example(causal=False)
    print("取消遮罩后，第一个位置的输出：", fmt(unmasked[0]))


demo_attention()

# 实验一：第三行换得面目全非，前两行能察觉吗？
future_changed = [[1, 0], [0, 1], [20, -20]]
original, weights = attention_example()
changed, _ = attention_example(inputs=future_changed)
assert original[:2] == changed[:2]
print("有遮罩：改动未来，前两个输出保持不变。")

# 实验二：撤掉遮罩，相当于把答案页翻到了桌面上。
unmasked, _ = attention_example(causal=False)
unmasked_changed, _ = attention_example(causal=False, inputs=future_changed)
assert unmasked[0] != unmasked_changed[0]
print("无遮罩：未来确实影响了第一个输出。")

# 实验三：只换取回的内容，匹配比例仍是原来那一份。
other, other_weights = attention_example(value_scale=4)
assert weights == other_weights
print("V 的第二维再翻倍，末尾输出：", fmt(other[-1]))

# 顺手核对概率总和、因果方向，以及手算公式。
assert all(abs(sum(row) - 1) < 1e-12 for row in weights)
assert all(weights[i][j] == 0 for i in range(3) for j in range(i + 1, 3))
r = math.exp(1 / math.sqrt(2))
expected = [1 / (2 + r), 1 / (2 + r), r / (2 + r)]
assert all(abs(a - b) < 1e-12 for a, b in zip(weights[-1], expected))
print("注意力计算核对通过。")
```

程序会打印正文中的 A 和 A@V。留意后面三条结果：

```text
有遮罩：改动未来，前两个输出保持不变。
无遮罩：未来确实影响了第一个输出。
V 的第二维再翻倍，末尾输出： [0.751745, 3.006980]
```

第一个实验把第三行换成 `[20,-20]`，前两个位置仍然看不见它；第二个实验撤掉遮罩，变化立刻能传回前面；第三个实验只改 V，匹配比例没动，取回的内容却变了。

这三次对比让“谁能提供信息”和“提供了什么信息”分开接受检查。数组尺寸正确只是能上桌，计算关系正确才算菜做对了。

## 9. 练习与解答

先猜结果，再解释原因。尤其是下面第二题：它专门检查我们有没有把“权重很大”误当成“输出一定不同”。

**题一：** 为什么查询位置 0 可以看自己，却不算偷看答案？

**解答：** 位置 0 的输入是当前已知 Token，它的目标是位置 1 的 Token。包含自己仍只使用前缀；允许读取位置 1 才可能直接看到目标。

**题二：** 如果 Q、K 不变，所有 V 都变成 `[3,7]`，每个位置的注意力输出是什么？

**解答：** 都是 `[3,7]`，因为每行权重之和为 1。权重可以不同，但相同内容的加权平均不变。这也说明仅看权重大小不足以解释最终信息贡献。

**题三：** 有 5 个位置，每个头的 Key 宽度为 8，单头 Q、Kᵀ、分数矩阵形状各是什么？

**解答：** `(5,8)`、`(8,5)`、`(5,5)`。缩放除以 √8，不是 √5；5 是位置数，8 才是点积里相加的维度数。

**题四：** 两个头各输出 `(5,8)`，拼接后是什么形状？若 d_model=16，W_O 怎样安排？

**解答：** 拼接为 `(5,16)`，可乘 `(16,16)` 的 W_O。拼接沿特征维发生，不会变成十个 Token。

**题五：** 为什么把未来分数改成 0 仍然有信息泄漏？

**解答：** Softmax 会将 0 变为指数值 1，未来位置仍分到非零权重，其 V 仍进入输出。需要在 Softmax 前正确屏蔽，或仅计算允许的前缀。
