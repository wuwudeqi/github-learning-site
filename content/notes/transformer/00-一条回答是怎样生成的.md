# 一条回答是怎样生成的

你输入“小猫饿了，请接着写”，屏幕上出现“它跑向食盆”。如果只解释为“模型理解问题，再生成答案”，几乎没有增加任何知识。我们需要继续追问：文字在哪里变成数字？网络究竟算出了什么？为什么下一次可能换一种说法？这些能力又是怎样学出来的？

这套教材会沿着一次续写，把这些问题逐个打开。主线采用**根据已有前缀预测下一个 Token 的 Decoder-only Transformer**。你不必先熟悉微积分；会做乘加、能读简单 Python，就可以从例子进入。遇到梯度和矩阵时，第 01 章提供可手算的补充。

读完后，应当能跟踪一段文字经过网络的计算，算出一次注意力和一次参数更新，并解释生成、训练与缓存之间的关系。

## 1. 先跟踪三次生成，而不是记一张架构图

假设某个已经训练好的模型正在续写“小猫饿了，它”。为了让过程看得清，先假定分词结果是 `[小猫, 饿了, ，, 它]`，并且接下来的三次选择如下：

| 这一步已有的前缀 | 模型要预测什么 | 生成程序选中什么 |
| --- | --- | --- |
| 小猫饿了，它 | 紧接在“它”后面的一个片段 | 吃 |
| 小猫饿了，它吃 | 紧接在“吃”后面的一个片段 | 鱼 |
| 小猫饿了，它吃鱼 | 后面继续写什么 | 结束标记 |

第二次计算已经能利用第一次写出的“吃”。这就是**自回归生成**：先选择一个单位，把它加入前缀，再计算下一步。Token 是模型处理的离散单位，可能是一个字、一个词或词的一部分，不能简单等同于汉字数。

这张表是说明流程的假设例子，不是下面小程序的实测输出。配套小模型没有学过语言，实际会重复“小猫”等片段；我们会保留这个结果，解释为什么“计算流程正确”与“已经有语言能力”不同。

现在先记住一个具体事实：**通常并不是先在某个数组中准备好整段答案，再一字一字显示出来。前一步的选择会成为后一步的条件。** 界面如何刷新文字，是另一层显示逻辑。

## 2. “预测下一个”究竟输出了什么

模型最后输出的是一组候选分数。为了能亲手算完，另用一个只有三个候选的分类例子，候选依次是“鱼、猫粮、球”。假设分数为：

```text
候选：      鱼       猫粮      球
分数：    ln(2)       0        0
约等于：   0.693      0        0
```

这些尚未归一化的分数叫 logits。用 Softmax 把它们转成概率：先取指数，再除以指数之和。

```text
取指数：      [2, 1, 1]
指数之和：     4
概率：        [0.50, 0.25, 0.25]
```

分数可以为负，概率不能为负。概率之和是 1，分数没有这种要求。模型计算出这些数以后，生成程序仍要决定如何选：

- **贪心选择**总是取最高分，本例选择“鱼”。
- **按概率采样**允许选中其他候选；重复很多次，选择比例才会逐渐反映这些概率。

这解释了为什么相同输入可能有不同输出。它也提醒我们：`P(鱼)=0.50` 是模型在当前条件下分配给某个候选的概率，不能直接解释成“这句话有 50% 的事实正确率”。[第 04 章](04-从网络层到生成循环.md)会算清输出分数、温度和采样的关系。

## 3. 打开中间那一步：分数从哪里来

先用无标点的短前缀“小猫饿了它”，跟踪配套程序的真实数据流：

```text
文字“小猫饿了它”
  ↓ 按教学词表切分、编号
[0, 1, 2]
  ↓ 查 Embedding 表，加入位置表示
3 行向量，每行 4 个数
  ↓ 注意力：让每个位置按不同权重汇入前缀信息
3 行经过信息混合的向量
  ↓ 残差、归一化、前馈网络等计算
3 行上下文表示
  ↓ 取最后一行，乘输出矩阵
词表中 6 个候选的分数
  ↓ Softmax 与生成策略
一个被选中的 Token
```

这里每一步都有具体问题，后面会用数值作答。

**编号为什么还要查表？** 编号只表示“是哪一项”。“鱼”的编号比“小猫”大，不表示鱼有更多某种属性。Embedding 把编号映射成可供后续计算的一组数，第 02 章会列出完整表格。

**为什么要让位置之间交换信息？** “它”最初查到的向量并不知道前面是小猫还是小狗。注意力可以把其他位置的信息混入当前位置的表示。第 03 章会完整算出匹配分数、遮罩、权重和加权结果。

**为什么只用最后一行预测新 Token？** 因果模型中，每一行只使用自己及之前的信息。最后一行才对应整个当前前缀；较早的一行是在预测那个较早前缀的后续。第 04、05 章会把这件事分别接到生成和训练上。

不要把向量的某一维预先命名为“饥饿程度”，也不要把注意力图里的一个大数字直接读成“模型已经理解了指代”。先把计算与证据看清，再讨论表示可能学到了什么。

## 4. 聊天窗口里的最后一句话，通常不是全部输入

比较这两段输入：

```text
A：小猫饿了。请接着写一句话。
B：把“小猫饿了”翻译成英文。
```

它们都提到小猫，但任务不同。系统必须把任务要求一并交给模型。聊天应用通常按模型要求的模板组织角色和消息，类似：

```text
[系统消息] 你是一个写作助手。
[用户消息] 小猫饿了。请接着写一句话。
[助手消息] 从这里开始生成……
```

方括号只是解释标签，实际模板可能使用专门的控制 Token。格式需要与模型的训练约定匹配。[Hugging Face 对话模板说明](https://huggingface.co/docs/transformers/main/en/chat_templating)

再加一个容易判断的情境：你昨天说过“我的猫叫团团”，今天问“它叫什么”。如果“团团”既没有进入本次上下文，也没有被其他机制提供，就不能仅凭聊天界面还显示旧记录，认定模型这次看到了名字。

“上下文”应理解成**本次计算实际能利用的信息**。历史消息、检索资料和工具结果只有经过选择、组织并进入输入，才能作为这次回答的条件。增加输出长度并不会自动补回遗漏的输入。

## 5. 模型为什么会给合理候选更高的分数

目前我们一直假设模型已经有了一组有用参数。训练负责改变这些参数。

仍用教学词表，准备一段文本：

```text
[小猫, 饿了, 它, 吃, 鱼, <结束>]
```

从中可以构造多个预测任务：

| 模型能看到的前缀 | 训练材料里实际紧接的目标 |
| --- | --- |
| 小猫 | 饿了 |
| 小猫 饿了 | 它 |
| 小猫 饿了 它 | 吃 |
| 小猫 饿了 它 吃 | 鱼 |
| 小猫 饿了 它 吃 鱼 | 结束标记 |

假如模型给正确目标“吃”的概率很低，损失就较大。反向传播计算哪些参数怎样影响这个损失，优化器再据此更新参数。训练材料提供了后续文本，因此不需要为每个前缀人工列出所有可选词。

这不是说任何训练文本都只有一种合理续写。“小猫饿了它”可以接“睡着了”，但当前样本提供的是“吃”。模型从很多样本中学习分布；单条样本的目标不能代表全部合理语言。

第 01 章先用打印费用算清“预测 → 损失 → 梯度 → 更新”；[第 05 章](05-模型怎样从文本中学习.md)再把这个循环换成 Token 概率，并真的更新一次输出矩阵。

## 6. 参数、上下文、缓存和工具，各自解决什么问题

这些机制都会影响你看到的回答，但不能互相替代。

| 对象 | 里面是什么 | 具体作用 |
| --- | --- | --- |
| 模型参数 | Embedding、投影矩阵等可学习数值 | 决定当前网络怎样计算；训练可以改变它们 |
| 上下文 | 本次提供的 Token 序列 | 告诉模型这次在什么条件下续写 |
| KV Cache | 当前前缀在各层算出的 K、V | 生成时复用中间结果，减少重复计算 |
| 产品保存的记录 | 历史对话、文件、用户设置等 | 经产品选择后，可以成为新的输入 |
| 外部工具 | 搜索、计算、数据库等程序 | 执行模型自身计算之外的操作，结果可再送回模型 |

例如问“附近宠物店今天几点关门”：模型可以生成一个搜索请求；应用执行搜索，将结果作为新输入；模型再据此组织回答。是否能搜索、工具怎样执行、结果有没有被传回来，都是整个系统的组成部分。单靠一层注意力不会自动访问互联网。

缓存也不会替你搜集新事实。它保存的是已有前缀的计算结果。[第 04 章](04-从网络层到生成循环.md)会验证缓存和完整重算的一致性，并说明何时必须重新计算。

## 8. 先试着解释这四个现象

**现象一：** 同一个模型，加上“用英文回答”后输出改变了。这能证明参数更新了吗？

**解释：** 不能。输入条件改变就足以改变概率。只有发生参数更新，才是这里所说的训练。可类比同一收费公式输入不同页数，费用也会改变。

**现象二：** 模型已经算过“小猫饿了它”，为什么选出“吃”以后还要继续算？

**解释：** 下一次要预测的是“小猫饿了它吃”的后续，新 Token 改变了条件。缓存能保留旧位置的中间结果，但仍要处理新位置并计算新的候选分数。

**现象三：** 回答写得更长，是否就能弥补它没看到某份文件？

**解释：** 不能由长度推出这一点。应先检查文件内容有没有进入输入，再判断模型怎样使用它；继续生成本身不会把缺失文件变进上下文。

**现象四：** 小程序每步都输出了概率，概率之和也是 1，为什么还是胡乱续写？

**解释：** 合法的概率分布只证明输出形式成立。权重还需要通过合适数据和训练目标形成有用的映射，并用未参与训练的例子验证能力。
