# 从网络层到生成循环

上一章忙了半天，端出来的是 `[0.751745,1.503490]`，小猫还是没吃上鱼。别急，注意力本来就只负责组合信息。接下来我们把剩下的工序接齐：**向量怎样走过一整层网络，变成候选分数，再一轮轮生成文字。**

这次回到六项词表、四维输入，搭一个叫 `TinyDecoder` 的小模型。它只有一层、一个头，权重用固定随机种子初始化，还没上过中文课。我们先检查它的计算是否完整，再讨论它为什么说不出漂亮话。

## 1. 为什么注意力外面还包着其他运算

注意力已经解决“从哪里取什么”。但整层网络还得回答三个问题：旧表示要不要留一份？数字越算越大或越小怎么办？汇进来的信息，还能怎样加工？残差、归一化和前馈网络就在这里接班。

本书采用一种常见的 Pre-LN 排列，LN 表示 LayerNorm：

```text
X：当前输入
│
├───────────────┐
↓               │
LN → 因果注意力  │
↓               │
与 X 相加 ←─────┘  得到 U
│
├───────────────┐
↓               │
LN → 前馈网络    │
↓               │
与 U 相加 ←─────┘  得到 H
```

这里的注意力子层包括输出投影 W_O。写成两行就是：

```text
U = X + AttentionSubLayer(LN(X))
H = U + FFN(LN(U))
```

Pre-LN 指归一化位于子层之前。原始 Transformer 论文采用的归一化位置不同；不能把本书这两行当成所有架构唯一的排列。先学会顺着计算图识别每个操作，再比较变体。

### 1.1 残差：把原来的表示也放进结果

`x+F(x)` 叫残差连接。用一个独立的二维小算术说明：

```text
x    = [1, 2]
F(x) = [0.1, -0.2]
输出 = [1.1, 1.8]
```

如果 F 暂时交了白卷，输出全是 0，结果也还保留着 x。你可以把它理解成保留原稿、再加修订：网络学习怎样修正已有表示。求导时，这条直接相加的路径也给梯度留了一条通路，有助于优化深层网络；但有了通路，训练仍要认真做。

逐项相加要求形状一致。这也是注意力拼接后的结果要投影回 d_model、前馈网络扩宽后又回到 d_model 的原因之一。

### 1.2 LayerNorm：在一个位置的特征维上调整尺度

先看向量 `[1,3]`：均值为 2，减均值后是 `[-1,1]`，平方差的平均为 1。归一化写成：

```text
归一化结果 = (x - 均值) / sqrt(方差 + epsilon)
```

取 `epsilon=0.00001`，结果约为 `[-0.999995,0.999995]`。epsilon 避免方差为 0 时除以 0。

常规 LayerNorm 还可以有可学习的逐维缩放 γ、偏移 β，即 `γ×归一化结果+β`。下文代码把 γ 固定为 1、β 固定为 0。对于 `(B,T,d_model)` 的输入，我们只在每个位置的最后一维归一化，没有把整篇文章或整个批次混起来求均值。[PyTorch LayerNorm 定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.LayerNorm.html)

LayerNorm 做完，只是这一行数的尺度调整了，负数照样可以出现。别看到“归一化”就以为它变成了概率：这里没有要求大家加起来等于 1。

### 1.3 前馈网络：每个位置分别做一段非线性变换

本实验选用：

```text
FFN(r) = ReLU(r @ W_1) @ W_2

r:      (1,4)
W_1:    (4,8)    → 中间表示 (1,8)
ReLU:            → 形状不变，负数置 0
W_2:    (8,4)    → 回到 (1,4)
```

所有位置拿的是同一套工具 W_1、W_2，放进去的原料却各不相同。前馈网络逐行加工，不直接把位置 i、j 混在一起；不过原料先经过了注意力，每行里已经可以带着前文的信息。

ReLU 使这段变换不能简单合并成一个线性矩阵，第 01 章的阶梯收费给出了手算解释。真实模型可能使用其他激活、门控或偏置，本实验省去这些变化，保持数据流可读。

## 2. 用完整形状追踪四维模型

输入仍为 `[小猫,饿了,它] → [0,1,2]`。每行采用第 02 章的 `Embedding+位置向量`，得到 X。

| 步骤 | 使用的参数或运算 | 本例输出形状 |
| --- | --- | --- |
| 输入 | 查表并加入位置 | `(3,4)` |
| 第一次归一化 | 每行 LN | `(3,4)` |
| Q、K、V | 分别乘三个 `(4,4)` 矩阵 | 各为 `(3,4)` |
| 注意力分数 | Q@Kᵀ/√4，加因果遮罩 | `(3,3)` |
| 信息混合 | 每行 Softmax 后乘 V | `(3,4)` |
| 注意力输出投影 | 乘 W_O `(4,4)` | `(3,4)` |
| 第一次残差 | 加回 X，得到 U | `(3,4)` |
| 前馈计算 | LN，再经过 `4→8→4` | `(3,4)` |
| 第二次残差 | 加回 U，得到 H | `(3,4)` |
| 末尾归一化 | 本模型在输出层前再做 LN | `(3,4)` |
| 输出分数 | 乘 W_vocab `(4,6)` | `(3,6)` |

堆叠多层时，上一层 H 会进入下一层，各层通常有各自的参数。本模型只放一层，并且没有 dropout，也没有在这些投影中使用偏置。

最后为什么是 `(3,6)`？三个输入位置各自都有六个候选分数。位置 0 预测“小猫”之后的候选，位置 1 预测“小猫饿了”之后的候选，位置 2 预测完整当前前缀之后的候选。因此生成新 Token 时使用最后一行。

## 3. 真实运行这组参数，看看它会选什么

完整前向程序放在下面，整段保存成 `main.py`，执行 `python3 main.py` 即可。先按四块阅读：词表与向量表、基础运算、`TinyDecoder` 模型类、末尾的实际调用。

第一次重点追踪 `forward`；`step` 是同一个模型的缓存入口，第 6 节会继续解释。这里没有留给其他文件代劳的隐藏函数，连随机种子也写出来了。

```python
import math
import random


TOKENS = ["小猫", "饿了", "它", "吃", "鱼", "<结束>"]


EMBEDDINGS = [
    [1.0, 0.0, 0.5, -0.5],
    [0.0, 1.0, -0.5, 0.5],
    [1.0, 1.0, 0.5, 0.5],
    [0.5, -0.5, 1.0, 0.0],
    [-0.5, 0.5, 0.0, 1.0],
    [0.0, 0.0, -0.5, -0.5],
]


def encode(text):
    """仅演示按词表最长匹配；不实现真实 BPE，也不忽略空格等字符。"""
    ids, offset = [], 0
    candidates = sorted(range(len(TOKENS)), key=lambda i: -len(TOKENS[i]))
    while offset < len(text):
        found = next((i for i in candidates if text.startswith(TOKENS[i], offset)), None)
        if found is None:
            raise ValueError(f"教学词表不支持位置 {offset} 的文本：{text[offset:]!r}")
        ids.append(found)
        offset += len(TOKENS[found])
    return ids


def decode(ids):
    return "".join(TOKENS[i] for i in ids)


def dot(a, b):
    if len(a) != len(b):
        raise ValueError("点积的两个向量必须等长")
    return sum(x * y for x, y in zip(a, b))


def linear(row, weights):
    return [dot(row, col) for col in zip(*weights)]


def add(a, b):
    if len(a) != len(b):
        raise ValueError("相加向量必须等长")
    return [x + y for x, y in zip(a, b)]


def softmax(scores):
    maximum = max(scores)
    # 减最大值不改变概率，可以避免 exp(1000) 这样的溢出。
    terms = [math.exp(s - maximum) for s in scores]
    total = sum(terms)
    return [t / total for t in terms]


def position_vector(position, width=4):
    result = []
    for pair in range(width // 2):
        angle = position / (10000 ** (2 * pair / width))
        result.extend([math.sin(angle), math.cos(angle)])
    return result


def layer_norm(row, epsilon=1e-5):
    mean = sum(row) / len(row)
    variance = sum((x - mean) ** 2 for x in row) / len(row)
    # 为看清计算，固定可学习缩放 gamma=1、偏移 beta=0。
    return [(x - mean) / math.sqrt(variance + epsilon) for x in row]


def attend(query, keys, values):
    scores = [dot(query, key) / math.sqrt(len(query)) for key in keys]
    weights = softmax(scores)
    mixed = [sum(w * row[c] for w, row in zip(weights, values)) for c in range(len(values[0]))]
    return mixed, weights


class TinyDecoder:
    """单层单头、四维 Pre-LN Decoder，ReLU FFN；无 dropout。"""

    def __init__(self):
        rng = random.Random(7)

        def matrix(rows, cols):
            return [[rng.uniform(-0.5, 0.5) for _ in range(cols)] for _ in range(rows)]

        self.wq, self.wk, self.wv, self.wo = [matrix(4, 4) for _ in range(4)]
        self.w1, self.w2 = matrix(4, 8), matrix(8, 4)
        self.head = matrix(4, len(TOKENS))

    def input_row(self, token, position):
        return add(EMBEDDINGS[token], position_vector(position))

    def finish_block(self, x, attention_output):
        u = add(x, linear(attention_output, self.wo))
        expanded = linear(layer_norm(u), self.w1)
        activated = [max(0.0, value) for value in expanded]
        h = add(u, linear(activated, self.w2))
        return layer_norm(h)

    def forward(self, ids):
        if not ids:
            raise ValueError("至少提供一个输入 Token")
        xs = [self.input_row(token, i) for i, token in enumerate(ids)]
        normalized = [layer_norm(x) for x in xs]
        qs = [linear(x, self.wq) for x in normalized]
        ks = [linear(x, self.wk) for x in normalized]
        vs = [linear(x, self.wv) for x in normalized]
        hidden, logits = [], []
        for i, query in enumerate(qs):
            mixed, _ = attend(query, ks[: i + 1], vs[: i + 1])
            h = self.finish_block(xs[i], mixed)
            hidden.append(h)
            logits.append(linear(h, self.head))
        return hidden, logits

    def step(self, token, cache):
        # 第一个位置为 0；已有 K 的数量就是新 Token 的绝对位置。
        x = self.input_row(token, len(cache["k"]))
        norm = layer_norm(x)
        q, k, v = linear(norm, self.wq), linear(norm, self.wk), linear(norm, self.wv)
        cache["k"].append(k)
        cache["v"].append(v)
        mixed, _ = attend(q, cache["k"], cache["v"])
        return linear(self.finish_block(x, mixed), self.head)


def fmt(row):
    return "[" + ", ".join(f"{x:.6f}" for x in row) + "]"


model = TinyDecoder()
ids = encode("小猫饿了它")
hidden, logits = model.forward(ids)
print("末尾表示 h：", fmt(hidden[-1]))
print("词表 logits：", fmt(logits[-1]))
print("词表概率：", fmt(softmax(logits[-1])))
```

这组参数最后一个位置的表示为：

```text
h ≈ [1.605306, -0.878187, -0.803641, 0.076522]
```

h 乘 `(4,6)` 的输出矩阵，得到以下六个分数。Softmax 后的概率也由脚本实际计算：

| 候选 | logit | 概率 |
| --- | ---: | ---: |
| 小猫 | 0.237411 | 0.306015 |
| 饿了 | −0.774329 | 0.111263 |
| 它 | −1.194914 | 0.073062 |
| 吃 | −0.665467 | 0.124059 |
| 鱼 | −0.369711 | 0.166753 |
| 结束 | −0.097843 | 0.218849 |

冠军是“小猫”，于是贪心选择它，句子就成了“小猫饿了它小猫”。读起来有点卡壳？正常，这位实习生还没学过中文。固定随机种子只是让每次实验可重复，不会顺手赠送语言能力。

我们就把这个不太体面的结果保留下来。网络结构让计算跑通，有用的参数要靠训练获得。若悄悄把输出换成一句好听的话，最值得学的这件事反而被藏起来了。

## 4. 从分数到选择：温度改变了哪里

贪心选择等于 `argmax(logits)`。Softmax 保持分数的大小次序，因此若只做贪心，其实可以直接比较分数。

采样时则按概率抽取候选。温度 τ 大于 0 时，常用 `softmax(logits/τ)` 调整分布。另用第 00 章的三候选例子，确保变化能算清：

| 温度 | 分数除以温度后的指数 | 概率 |
| ---: | --- | --- |
| 1 | `[2,1,1]` | `[0.5000,0.2500,0.2500]` |
| 0.5 | `[4,1,1]` | `[0.6667,0.1667,0.1667]` |
| 2 | `[√2,1,1]` | `[0.4142,0.2929,0.2929]` |

对这组分数，降温后第一名更占优势，升温后其他候选也更有机会。这里改的是选择前的分布，没有更新模型参数；温度旋钮不附带补课功能。

τ=0 不能直接代进除法。生成程序若提供“温度 0”的设置，通常需要把它解释成某种确定性选择分支，而不是计算除以 0。不同接口还可能另外提供 top-k、top-p 等筛选，使用时应看具体实现。

所以，更果断不等于更正确。如果错误候选本来就排第一，贪心也会选错。降低温度，可能只是让它更坚定地选错；事实是否可靠，还得看模型、输入和证据。

## 5. 先写最直观的生成循环

把下面这段接在第 3 节完整程序的末尾，复用同一文件中已经定义的 `TinyDecoder`、词表和函数。每一步先完整重算前缀，让生成顺序清清楚楚地摆出来：

```python
# 接在第 3 节完整程序后面；这里复用已定义的模型与词表。
model = TinyDecoder()
ids = encode("小猫饿了它")
for _ in range(4):
    _, logits = model.forward(ids)
    scores = logits[-1]
    next_id = max(range(len(TOKENS)), key=lambda i: scores[i])
    ids.append(next_id)
    if TOKENS[next_id] == "<结束>":
        break
print(decode(ids))
```

四步依次选择“小猫、小猫、吃、鱼”，最终打印：

```text
小猫饿了它小猫小猫吃鱼
```

看起来像打字时手抖了两下，其实是未训练的参数在照常工作。停止条件有两个：选中结束标记，或达到四个新 Token 的上限；本次触发的是后者。这个上限由生成程序执行，小网络不会因为我们写了个 `4` 就突然懂得“适可而止”。

这个循环有点勤快过头：来了第四个位置，前三个位置的作业又重抄一遍。结果可以算对，但算过的内容里，有一部分其实能留着下次用。

## 6. KV Cache 为什么可以复用旧结果

有因果遮罩时，前三个位置不能看第四个位置。因此在**参数、输入前缀、位置设置和确定性计算都保持一致**的条件下，追加第四个 Token 不会改变前三个位置已有的表示。

这一点也适用于多层：每层旧位置只能依赖前面各层的旧前缀，不会突然收到新位置的信息。所以各层过去算出的 K、V 可以保存。

缓存准备好以后，新 Token 来报到，就按下面的步骤继续：

```text
为新位置计算 Q_new、K_new、V_new
把 K_new、V_new 追加到对应层的缓存
用 Q_new 与所有可见 K 打分
用得到的权重组合所有可见 V
继续完成新位置的残差、前馈网络和输出层
```

为什么通常缓存 K、V，不保留全部旧 Q？新位置需要查询旧来源，因此需要旧 K 和旧 V；旧位置的 Query 不再负责这次新增位置的输出。[Hugging Face 缓存机制说明](https://huggingface.co/docs/transformers/en/cache_explanation)

初次处理整个已知提示词的阶段常称为 prefill，之后逐个产生新 Token 的阶段称为 decode。实际实现通常会批量处理 prefill；本脚本为了展示等价性，用 `step` 逐个填充同一前缀的缓存，再比较结果。

### 6.1 缓存省掉了什么，没有省掉什么

前缀长度为 N 时，完整重算要形成 N×N 的注意力关系；新增位置只需形成一行、与 N 个已有位置建立关系。单头的这部分匹配工作从大约 `N²×d_k` 变成 `N×d_k`，同时省去旧位置反复做的投影与前馈运算。

不过，“不用重抄”不等于“完全不用看旧内容”。新位置仍要查询过去的 K、V，前缀越长，这一部分工作与缓存存储也会增长。

若有 L 层、批量 B、T 个位置、H_kv 个 K/V 头、每头宽度 d、每个数 s 字节，简单完整缓存的存储量为：

```text
2 × L × B × T × H_kv × d × s 字节
↑
K 和 V 各存一份
```

假设 L=2、B=1、T=1000、H_kv=2、d=4、s=4，得到 128000 字节，约 125 KiB。这只是按参数计算的示例，不包含模型权重、临时张量、容器开销或额外缓存元数据。

### 6.2 哪些改变会使旧缓存不再适用

如果把前缀第一项从“小猫”改成“它”，相关表示已经变了，不能继续把旧 K、V 当成新输入的结果。改变模型权重、位置编号或注意力设置，也需要重新判断缓存是否仍有效。

有个常见坑：每来一个新 Token，都给它填位置 0。这样大家全住进“0 号房”，位置向量当然对不上。正文里的 `step` 用当前缓存长度作新位置编号，才与完整计算保持一致。

缓存存着已算过的前缀，不是失物招领处。某段文字若没有进入输入，KV Cache 不能替你把它找回来。

## 7. 用相等与不相等，检查实现的边界

下面这段也接在同一文件末尾。先用完整前缀计算所有位置，再用缓存逐个计算；随后改动未来输入，最后跑一次带缓存的生成：

```python
# 接在前面的代码后面。先核对每个位置，再做缓存生成。
model = TinyDecoder()
ids = [0, 1, 2, 3, 4]
_, full_logits = model.forward(ids)
cache = {"k": [], "v": []}
cached_logits = [model.step(token, cache) for token in ids]
max_error = max(
    abs(a - b)
    for full_row, cached_row in zip(full_logits, cached_logits)
    for a, b in zip(full_row, cached_row)
)
assert max_error < 1e-10
assert len(cache["k"]) == len(ids) == len(cache["v"])
print(f"所有位置的缓存最大误差：{max_error:.2e}")

# 未来换了内容，前两行的结果也不能跟着改口。
_, changed_logits = model.forward([0, 1, 4, 5, 2])
assert all(
    abs(a - b) < 1e-10
    for i in (0, 1)
    for a, b in zip(full_logits[i], changed_logits[i])
)
print("整层网络的因果性检查通过。")

# 用同一个前缀填充新缓存；旧缓存不能跨输入随便借来用。
ids = encode("小猫饿了它")
cache = {"k": [], "v": []}
for token in ids:
    scores = model.step(token, cache)

for step in range(4):
    _, full = model.forward(ids)
    error = max(abs(a - b) for a, b in zip(full[-1], scores))
    assert error < 1e-10
    next_id = max(range(len(TOKENS)), key=lambda i: scores[i])
    print(f"第 {step + 1} 步：选择 {TOKENS[next_id]}，缓存误差 {error:.2e}")
    ids.append(next_id)
    if TOKENS[next_id] == "<结束>" or step == 3:
        break
    scores = model.step(next_id, cache)
print("缓存版最终文本：", decode(ids))
```

两类关键检查各有明确用途：

| 检查 | 应当发生什么 | 能发现什么问题 |
| --- | --- | --- |
| 用完整前缀算每个位置，再逐个用缓存计算 | 对应位置的分数在误差范围内相等 | 位置偏移、缓存追加、注意力范围错误 |
| 保持前两项不变，只修改后面的 Token | 前两个位置的输出保持相等 | 网络某处泄漏了未来信息 |

这里逐项比较分数，不只比较最后选出的 Token。两张计分板可以都有同一个冠军，其他名次和分数却完全不一样；只看冠军，会漏掉不少错误。

默认四步生成的缓存误差都为 0，最终文本与第 5 节相同。不同计算顺序与精度可能产生很小的浮点差异，因此代码使用误差范围判断，不要求所有后端逐比特一致。

## 8. 与 Encoder、Decoder、聊天助手的关系

“Transformer”并不只对应本书这一种结构。

| 结构情境 | 输入可见性与信息来源 | 典型问题 |
| --- | --- | --- |
| 双向编码器 | 处理已给出的完整输入，允许位置利用两侧信息 | 对整句分类或形成输入表示 |
| 编码器—解码器 | 编码源输入，目标侧因果生成，并可交叉查询源表示 | 根据源句生成译文 |
| 本书的 Decoder-only | 在同一条序列上通过因果自注意力处理提示词与续写 | 根据前缀逐步生成 |

本模型没有独立的编码器，也没有交叉注意力；这不表示输入完全没有被加工，输入仍会经过每一层的计算。名称中的 Decoder 需要结合结构理解。

聊天角色、工具执行、文件检索属于围绕模型组织的流程，不能从这个四维网络的结构图推出产品具备哪些功能。它能解释核心生成机制，产品能力还取决于训练与外部系统。

## 9. 练习与解答

**题一：** 三个位置、表示宽度 4、词表 6 项，输出矩阵和所有 logits 的形状分别是什么？为什么生成时不用第一行？

**解答：** 输出矩阵 `(4,6)`，logits 为 `(3,6)`。第一行只对应第一个 Token 的前缀；最后一行才利用整个当前前缀。

**题二：** 如果注意力子层返回全零，第一次残差输出是什么？这是否意味着整个网络输出就等于原输入？

**解答：** U=X。后面仍有归一化、前馈网络、第二次残差和输出层，因此不能直接推断最终输出等于 X。

**题三：** 同一模型打开缓存后，出现明显不同的候选分数，能解释成“缓存让模型有了另一种思考方式”吗？

**解答：** 不应这样解释。在等价条件成立时，缓存复用既有计算。应优先检查前缀、位置、参数、遮罩、精度与缓存管理是否一致。

**题四：** 新 Token 的 Q 已经算出，为什么仍不能只用新 K、V？

**解答：** 它需要根据当前查询利用已有上下文。只保留新 K、V 就把来源限制成自己，改变了注意力的输入范围，通常也改变了计算结果。

**题五：** 用同样的采样策略多生成四个 Token，可以让本章随机模型突然学会语言吗？

**解答：** 没有发生参数训练。生成会改变上下文，但不能把“完成更多次前向计算”当成“已经学到了好的语言参数”。下一章处理的正是参数怎样更新。
