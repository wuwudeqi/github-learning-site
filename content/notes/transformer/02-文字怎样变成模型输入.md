# 文字怎样变成模型输入

总览里，文字最终变成了数字。现在我们追踪“小猫饿了它”这个短前缀，直到得到可以交给网络的输入矩阵。这个句子省去了标点，只为减少手算工作；真实模型会处理标点和空格，不能在实际任务中随意删掉它们。

本章的目标是：看到一组编号和一张数字表时，能判断它们分别来自哪里、各行各列代表什么，以及哪些数值会通过训练改变。

## 1. 先规定一个只有六项的词表

把我们的教学程序允许使用的片段列出来：

| 编号 | 文本片段 |
| --- | --- |
| 0 | 小猫 |
| 1 | 饿了 |
| 2 | 它 |
| 3 | 吃 |
| 4 | 鱼 |
| 5 | `<结束>` |

这张表叫词表。编码程序从左到右匹配其中的片段，于是：

```text
小猫饿了它 → [小猫, 饿了, 它] → [0, 1, 2]
```

解码时反过来查表：`[3, 4] → [吃, 鱼] → 吃鱼`。这里一个 Token 可以是两个汉字，也可以是一个汉字；编号只负责识别是哪一项。

假如把“鱼”和“小猫”的编号对调，并把输入 Embedding 的对应行、输出层的对应类别也一起对调，鱼不会因此变得更小，小猫也不会变得更多。编号的大小没有这样的语义。因此我们不会直接拿 `[0, 1, 2]` 当作三个具有数值大小含义的语言特征。

我们的最长匹配程序遇到“狗”会明确报错。真实分词器通常有更细的子词或字节等处理机制，不能从这个教学词表推断真实模型只能处理训练时见过的完整单词。

## 2. 真实分词为什么经常不像按词切分

如果把每一个完整词都放进词表，新词、拼写变化和代码名称会让词表很大。另一端，若每个字节都单独处理，一个长句又会占用很多位置。子词方法在片段大小和词表规模之间做取舍。

用一个极小的 BPE 合并过程理解思路。假设训练材料只有以下词和次数：

```text
low   出现 3 次
lower 出现 1 次
```

先从字符出发，忽略词边界细节：`l o w` 与 `l o w e r`。相邻的 `l-o` 和 `o-w` 都出现 4 次。如果规则在并列时先选 `l-o`，把它合并成 `lo`，下一次可以把 `lo-w` 合并成 `low`。继续训练会得到一套固定合并规则，编码新文本时按规则应用。

这个例子只展示“统计相邻片段并合并”的动作。真实 BPE 还涉及预切分、初始符号、边界和并列处理；WordPiece、Unigram 也有不同规则。分词器通常在模型使用之前准备好，聊天时不会临时为每个新句子重新训练它。[Hugging Face 分词算法说明](https://huggingface.co/docs/transformers/main/en/tokenizer_summary)

实际影响很具体：两个汉字不保证占两个 Token；英文空格可能属于某个 Token；相同句子在不同分词器下长度可能不同。估算上下文长度或费用时，需要使用目标模型对应的分词器。

## 3. 编号怎样查成向量

给每个编号配四个数，得到 Embedding 矩阵 E。下面是配套四维小模型的完整初始表，数值人为设定：

| Token | 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | ---: | ---: | ---: | ---: |
| 小猫 | 1 | 0 | 0.5 | -0.5 |
| 饿了 | 0 | 1 | -0.5 | 0.5 |
| 它 | 1 | 1 | 0.5 | 0.5 |
| 吃 | 0.5 | -0.5 | 1 | 0 |
| 鱼 | -0.5 | 0.5 | 0 | 1 |
| 结束 | 0 | 0 | -0.5 | -0.5 |

对输入 `[0, 1, 2]`，取第 0、1、2 行：

```text
E[0] = [1, 0,  0.5, -0.5]
E[1] = [0, 1, -0.5,  0.5]
E[2] = [1, 1,  0.5,  0.5]
```

这是一次查表。词表编号是离散的标识，E 的数值通常是模型中可学习的参数。完整训练会通过后面的计算把梯度传回被使用的向量；本书的最小网络先固定它们，以便每次能看到相同结果。

四列没有被命名为“动物、饥饿、性别、动作”。真实表示可以把信息分散在许多维度中。把某一维直接当成可读属性，会让比喻超出证据。

### 3.1 查表与 one-hot 有什么关系

“它”的编号是 2，也可以写成长度为 6 的 one-hot 向量：

```text
[0, 0, 1, 0, 0, 0] @ E
= 0×E[0] + 0×E[1] + 1×E[2] + ...
= E[2]
```

one-hot 的含义是“只有这一项被选中”。查表直接完成同一件事，不必显式创建一个大多为零的向量。这里的等价关系也解释了为什么 Embedding 能接上后面的矩阵计算。

### 3.2 同一个 Token 的向量为什么还能随语境变化

考虑“小猫饿了，它”和“小狗跑累了，它”这两个前缀。真实模型中，“它”若对应同一 Token，最初查到的 E 行相同；但前面的信息不同，位置也可能不同，经过后面的网络后，它的表示就可能改变。第二句话仅说明语境差异，不属于本章六项词表能编码的文本。

还要注意因果方向：若仅把“它吃鱼”改成“它睡觉”，保持“它”之前的输入和位置不变，本书的因果模型在“它”这个位置不能利用后面的变化，其表示应保持不变。讨论向量随语境变化时，应说清模型允许利用哪一部分语境。

## 4. 用形状检查自己有没有把表看反

本例有 6 个词表项，每项 4 个数，所以 `E` 的形状是 `(6, 4)`。输入有 3 个 Token，查表结果是 `(3, 4)`：

```text
编号：             (3,)
完整 Embedding：   (6, 4)
本次查出的向量：   (3, 4)
                   ↑  ↑
                 位置 特征
```

若同时处理两段文本，每段补齐到 3 个位置，批量形状通常写成 `(2, 3, 4)`，依次为批量数 B、序列长度 T、表示宽度 d_model。补齐用的 padding 位置需要相应屏蔽，不能把补齐内容当成真实文本或训练目标。

向量宽度与词表大小分工不同：宽度决定每个位置使用多少个数表示；词表大小决定输出时有多少类候选。在[第 04 章](04-从网络层到生成循环.md)中，末尾的四维表示会乘上 `(4, 6)` 的输出矩阵，得到六个候选分数。

## 5. 已经排成三行，为什么还需要位置表示

把“猫追狗”和“狗追猫”拆成同一组片段，顺序改变了谁追谁。数组里的行序让程序能按位置取数据，但如果一个不带位置机制的注意力运算只按内容做匹配，它本身不会自动知道“相隔两格”这样的距离。

先看没有因果遮罩的情况：同时把输入行重新排序，内容之间的匹配关系跟着重排，输出也跟着重排。因果遮罩进一步规定了谁能看谁，因此它已经带来方向性的顺序约束；位置机制则继续提供具体位置或相对距离信息。不能把二者说成完全相同的功能。

本书的四维网络使用正弦、余弦构造位置向量。对于从 0 开始的位置 p，四个数是：

```text
P(p) = [sin(p), cos(p), sin(p/100), cos(p/100)]
```

角度使用弧度。前一对变化快，后一对变化慢；更宽的向量会使用更多频率。下面直接把位置向量与 Token 向量逐项相加：

```text
位置 0 的“小猫”
E = [1, 0, 0.5, -0.5]
P = [0, 1, 0, 1]
X = [1, 1, 0.5, 0.5]

位置 1 的“饿了”
E = [0, 1, -0.5, 0.5]
P ≈ [0.841471, 0.540302, 0.010000, 0.999950]
X ≈ [0.841471, 1.540302, -0.490000, 1.499950]
```

这样，同一个 Token 出现在不同位置，输入向量会不同。这里的位置向量由公式计算，Embedding 表则是另一组参数。本实验为便于核对采用 `X=E+P`；不同架构可能采用额外缩放、可学习位置表或其他位置机制。[《动手学深度学习》位置编码章节](https://d2l.ai/chapter_attention-mechanisms-and-transformers/self-attention-and-positional-encoding.html)

## 6. RoPE、检索向量与这里是什么关系

### 6.1 RoPE 为什么叫旋转位置编码

RoPE 是另一种引入位置的方式，常把位置相关的旋转施加到注意力中的 Q、K。先看二维旋转的算术：

```text
R(θ) [x, y] = [x cosθ - y sinθ, x sinθ + y cosθ]
```

把 `[1, 0]` 旋转 90°，得到 `[0, 1]`。如果 Q 和 K 同时旋转同一个角度，点积不变；若两者转过不同角度，点积会受到角度差的影响。采用与位置相关的角度，就能使匹配计算利用相对位置信息。

真实 RoPE 在多对维度上使用不同频率。上述 90° 只是演算旋转，配套脚本仍使用前面的加法位置编码，没有偷偷换成 RoPE。[RoFormer 论文，第 3 节](https://arxiv.org/abs/2104.09864)

### 6.2 向量数据库里的 Embedding 就是这张表吗

不必是。向量检索常把一个句子或文档变成一个向量，用于比较查询与文档。这里每个 Token 查出的向量只是语言网络的输入。把 Token 向量随意平均，并不能自动得到经过检索目标训练的文档表示。

共同点是都用一组数字表示对象；区别是对象是什么、怎样得到向量、训练目标是什么。遇到“Embedding 相似度”时，应把这三个问题问清楚。[Sentence Transformers 语义搜索说明](https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)

## 7. 用脚本跟踪一遍，并故意制造一个错误

在专题目录运行：

```bash
python3 code/transformer_lab.py input
```

脚本会打印编号、每个位置的 E、P、X。对照前面的两个向量，检查相加结果。下载：[transformer_lab.py](code/transformer_lab.py)。下载后也可直接运行 `python3 transformer_lab.py input`。

再把 `demo_input` 中的文字改成“小狗饿了”。程序应报告教学词表无法匹配。这个失败来自编码阶段，尚未进入注意力。若你把错误归因为“模型没理解狗”，就把分词和网络计算混在一起了。

如果你给 TOKENS 增加“小狗”，还需要给 EMBEDDINGS 增加对应的一行。实际模型更换词表时也必须处理对应的输入、输出参数与训练，不能只改一张文本表。

## 8. 换条件练习与解答

**练习一：** 输入是“它吃鱼”，编号、输入向量形状分别是什么？

**解答：** 编号为 `[2, 3, 4]`，查表结果是 `(3, 4)`。词表仍是六项，不会因为这次只用三个片段变成三项。三个位置仍从 0 开始计算位置向量。

**练习二：** 五段文本各补齐到十个 Token，每个向量八维，输入形状是多少？为什么不能直接把 padding 当成训练目标？

**解答：** `(5, 10, 8)`。padding 是为了组织批量而补上的位置，训练损失若把它当真实目标，会引入额外的学习要求；注意力还需按任务屏蔽无效位置。

**练习三：** 将“它”从第 0 个位置移到第 2 个位置，哪些数不变，哪些数改变？

**解答：** 在本模型参数不变时，编号和查到的 E 行不变。P 改变，因此 X 改变；可见前缀也可能改变，后续上下文表示不能保证相同。

**练习四：** 两个 Token 初始向量相同，是否说明它们在任何句子中的作用都相同？

**解答：** 不能。位置、前缀和后续计算都会影响表示。不过如果其他条件也完全一样，这个模型就不能仅靠相同初始向量把它们区分开，这说明表示设计确实会限制可区分的信息。
