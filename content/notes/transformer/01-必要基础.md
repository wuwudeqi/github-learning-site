# 参数、预测与训练

语言模型会给下一个 Token 打分，可它最初凭什么打得准？参数总不能靠“我觉得这个数字挺顺眼”来定。我们先解决一个基础问题：**计算规则中的数字怎样从例子中慢慢变得有用？**

直接拿文字开练，分词、矩阵、概率和求导会一起上门，门口容易堵车。咱们先开一家虚构打印店：老板给三张旧小票，我们教程序估算新订单。整套训练能用纸笔算完，第 05 章再把费用换成 Token 概率。

价格特意凑成方便手算的整数，只用来理解训练。学会以后可以调参数，先别拿这张价目表去跟真实打印店老板砍价。

## 1. 模型是怎样的一条可调规则

历史订单如下：

| 页数 x | 实际费用 y |
| ---: | ---: |
| 1 | 2 |
| 2 | 4 |
| 3 | 6 |

你大概已经看出来：“这不就是每页 2 元吗？”对，但程序还是新来的实习生，咱们暂时不把答案写死。先给它一条能调数字的规则：

```text
预测费用 = 每页价格 × 页数 + 固定费用
  y_hat = w × x + b
```

x 是输入，y 是记录中的目标，y_hat 是当前预测；w、b 是所有订单共同使用的**参数**。暂时设 `w=1、b=0`，打印两页就预测 `1×2+0=2` 元，比目标 4 元少了 2 元。

这里有两种不同改变：

| 改变什么 | 计算 | 含义 |
| --- | --- | --- |
| 参数不变，页数从 2 换成 3 | 1×3+0=3 | 同一模型处理新输入 |
| 页数不变，把 w 调到 1.5 | 1.5×2+0=3 | 改变模型的参数 |

普通推理主要做第一类事；训练根据数据做第二类事。**模型结构规定允许怎样计算，参数决定当前具体算出什么。** 本例的结构只允许“乘后加”，训练不会自动把它改成一张任意收费表。

## 2. 算得好不好：为什么需要损失

比较两套参数，误差统一定义成“预测减目标”：

| 候选 | 三张订单的预测 | 三次误差 | 误差之和 |
| --- | --- | --- | ---: |
| A：w=1，b=0 | 1、2、3 | −1、−2、−3 | −6 |
| B：w=1，b=2 | 3、4、5 | +1、0、−1 | 0 |

B 的误差之和是 0，看起来像“账平了”。可第一位顾客多付的钱，没自动跑进第三位顾客的口袋。两张账单仍然错了：直接相加，会让多估和少估互相抵消。

先平方、再平均，就能避免抵消：

```text
L_A = [(-1)² + (-2)² + (-3)²] / 3 = 14/3 ≈ 4.666667
L_B = [(+1)² + 0² + (-1)²] / 3 = 2/3 ≈ 0.666667
```

L 叫损失。本章选的是均方误差，英文缩写 MSE。按这个标准，B 在这三张订单上更好。

为什么平方？除了消除正负，误差从 1 增加到 2 时，惩罚会从 1 增加到 4。为什么平均？避免仅仅因为订单变多，总损失就跟着增加。绝对误差等其他标准也可以使用，损失必须根据任务选择。

不过，`L=4` 像一张成绩单：分数写了，怎么进步还没写。要决定 w、b 往哪边改，得继续追踪“参数动一下，损失跟着怎么动”。

## 3. 不先背求导公式，也能看懂梯度

只看两页订单：`x=2、y=4`，从 `w=1、b=0` 出发。固定 b，试着把 w 改动一点：

| w | 预测 2w | 损失 (2w−4)² |
| ---: | ---: | ---: |
| 0.99 | 1.98 | 4.0804 |
| 1.00 | 2.00 | 4.0000 |
| 1.01 | 2.02 | 3.9204 |

试探有结果了：w 增大 0.01，损失反而减少 0.0796。往这边挪一小步似乎有用。把变化量除一下，就得到附近的变化率：

```text
(3.9204 - 4) / (1.01 - 1) = -7.96
```

试探幅度趋近于 0 时，这里的变化率趋近 −8。它叫损失对 w 的导数。多个参数各有一个这样的变化率，把它们放在一起，就是梯度。

这个负号不是在批评 w。它说的是“在这里增加 w，损失会往下走”。所以要降低损失，我们沿梯度的反方向更新。方向看清了，下一节再决定步子迈多大。

### 3.1 把 −8 的来路拆成三段

画出真实的计算顺序：

```text
w → y_hat=wx+b → e=y_hat-y → L=e²
```

在 `x=2、e=-2` 的这个点：

1. w 每变化一点，预测以 x=2 倍的速率变化。
2. 减去固定目标 y，不改变这个变化率。
3. 平方函数在 e 处的变化率为 2e，此处是 −4。

沿途变化率相乘，得到：

```text
dL/dw = 2e × 1 × x = 2 × (-2) × 2 = -8
dL/db = 2e × 1 × 1 = 2 × (-2)     = -4
```

这就是链式法则：变化沿计算路线传递，把路上的变化率乘起来。b 直接加到预测上，所以它对应的那一段变化率是 1。`dL/dw` 读作“损失对 w 的变化率”；有多个参数时也写成 `∂L/∂w`，表示考察 w 的变化时固定其他参数。

复杂网络只是计算路径更多。**反向传播**沿这些路径传回梯度；遇到一项通过多条路径影响损失，要把各条路径的贡献相加。它并不是让网络倒着生成文字。

### 3.2 为什么不永远靠加一点、减一点试探

本例只有两个参数，可以试。若有大量参数，逐个试探需要许多次计算。反向传播利用计算图组织求导，能共同计算这些参数的梯度。

小幅试探仍很有用：它可以独立核对求导代码。[第 05 章](05-模型怎样从文本中学习.md)会把输出层的解析梯度与中心差分逐项比较。

## 4. 算完一次训练，再故意让它失败

### 4.1 同时更新两个参数

最基本的梯度下降规则是：

```text
新参数 = 旧参数 - 学习率 × 梯度
```

学习率控制步幅。取 0.1：

```text
旧参数：w=1，b=0
旧预测：1×2+0=2
目标：4
误差：-2
梯度：w 对应 -8，b 对应 -4

新 w = 1 - 0.1×(-8) = 1.8
新 b = 0 - 0.1×(-4) = 0.4

新预测：1.8×2+0.4=4
新损失：(4-4)²=0
```

两个梯度都站在**同一组旧参数**上计算，然后一起更新。不要先改 w，再用新 w 算 b 的梯度，否则执行的就不是这里这一次更新。

![从预测、损失到反向传播和参数更新的训练过程](images/training.svg)

前向计算负责算预测和损失，反向传播负责算梯度，优化器负责按规则更新。本例的优化器使用普通梯度下降。

### 4.2 梯度方向正确，步子也可能迈错

每行都重新从 `w=1、b=0` 出发，使用同一组梯度：

| 学习率 | 新 w | 新 b | 对两页的预测 | 新损失 |
| ---: | ---: | ---: | ---: | ---: |
| 0.01 | 1.08 | 0.04 | 2.2 | 3.24 |
| 0.10 | 1.80 | 0.40 | 4.0 | 0 |
| 0.30 | 3.40 | 1.20 | 8.0 | 16 |

原来的损失为 4。0.30 这一步越过了目标，反而更差；继续用 0.30 更新一次，预测会变成 −4，损失扩大到 64。

梯度像当前位置的路标，学习率决定这一步跨多远。路标指向下坡，不代表可以闭眼冲出三公里。0.1 在本题一步到位，是这组数字恰好配合；换个模型，要重新判断步幅。

### 4.3 一张订单损失为 0，为什么还没学会规律

刚得到的 `w=1.8、b=0.4` 在其他页数上如何？

| 页数 | 目标 | 预测 |
| ---: | ---: | ---: |
| 1 | 2 | 2.2 |
| 2 | 4 | 4.0 |
| 3 | 6 | 5.8 |
| 4 | 8 | 7.6 |

一张订单只提出一个要求：`2w+b=4`。`w=2、b=0` 能交差，`w=1、b=2` 也能交差；甚至“每页不要钱，进门收 4 元”的 `w=0、b=4` 都能过关。证据只有一张小票，收费规则当然还定不下来。

把多张订单一起训练，就是要求同一组参数同时照顾它们。若损失取 n 张订单的平均，梯度也取平均：

```text
gw = sum(2 × 每张订单的误差 × 该订单页数) / n
gb = sum(2 × 每张订单的误差) / n
```

这里相加的是“同一个参数在不同样本上的梯度贡献”，不是给每张订单永久分配一套自己的参数。

## 5. 从一张订单走到矩阵乘法

换一个独立场景：黑白每页 0.5 元、彩色每页 1 元，固定费用 0.2 元。订单有两种输入，就按固定顺序放进向量：

```text
x = [2, 3]       # 黑白 2 页，彩色 3 页
w = [0.5, 1]     # 对应的两种单价
预测 = 2×0.5 + 3×1 + 0.2 = 4.2
```

对应位置相乘再相加，叫点积。这里它计算费用；在注意力里，点积会承担匹配打分的任务。同一种算术，不必只有一种含义。

加入另一张“黑白 1 页、彩色 4 页”的订单，把输入按行排起来：

```text
     黑白  彩色
X = [ 2,    3 ]
    [ 1,    4 ]

W = [ 0.5 ]
    [ 1.0 ]

X @ W = [ 4.0 ]   加 b=0.2 → [ 4.2 ]
        [ 4.5 ]              [ 4.7 ]
```

`@` 表示矩阵乘法。你可以把它读成“把这两张订单一起算”：每行仍做同样的点积，收费规则没有换，只是账单排成了表。

![每行订单乘以对应单价，再加入固定费用](images/matrix.svg)

如果有 5 张订单，每张 3 个特征，要分别输出 2 个数，可以使用：

```text
X: (5, 3)   @   W: (3, 2)   →   输出: (5, 2)
```

W 的每一列负责一个输出。中间的 3 要一致，保证每个输入特征都找到对应权重；外侧的 5 和 2 决定结果形状。

后面的教材统一把一个 Token 的表示写成行向量。`X` 的行会变成“位置”，列会变成“特征”，不再是订单与页数。**先说清行列含义，再检查形状**，比只背乘法口诀可靠。

## 6. 多接几层乘法，为什么还不够

假设收费改成“前两页每页 2 元，超过两页的部分每页 1 元”：

| 页数 | 费用 |
| ---: | ---: |
| 1 | 2 |
| 2 | 4 |
| 3 | 5 |
| 4 | 6 |

单个 `wx+b` 的每页增量永远是 w，不能同时满足两种斜率。延长训练解决不了这种表达限制。

多请一位“收费员”接力呢？先算 `h=2x+1`，再算 `y_hat=3h+4`，展开还是 `6x+7`。人手似乎增加了，规则仍是一条直线。一般地，只连接线性变换和偏置，最后仍能合并成一个仿射变换。

加入一个简单的转折函数 ReLU：

```text
ReLU(z) = max(0, z)
费用 = 2x - ReLU(x-2)
```

| x | x−2 | ReLU(x−2) | 最终费用 |
| ---: | ---: | ---: | ---: |
| 1 | −1 | 0 | 2 |
| 2 | 0 | 0 | 4 |
| 3 | 1 | 1 | 5 |
| 4 | 2 | 2 | 6 |

前两页不减价，之后每页减 1 元，恰好产生需要的转折。这个公式是手工构造的，证明了“可以表达”，还没有证明某个训练程序已经自己学会它。

Transformer 的前馈网络也把可学习变换与非线性连接起来。注意力负责让位置之间交换信息，前馈网络再对每个位置的表示进行变换。[第 04 章](04-从网络层到生成循环.md)会把这两部分接成一整层。

## 7. 从旧订单接回语言模型

如果程序把三张历史订单背下来，遇到其他页数一律输出 0，它在旧订单上全对，在新订单上却很差。我们需要关心**泛化**：面对没有用于训练的输入，学到的规则是否仍然有效。

训练集用来练，验证集帮你比较学习率等设置，测试集留到最后检查。若一边偷看测试结果，一边回头改方案，这套“考试题”就参与了训练方案的选择，分数也不再那么独立。

评估也可以计算损失，但不必更新参数。所以“有损失”不等于“正在训练”。换一家收费规则完全不同的店，又涉及输入或规律的变化，不能由这三张订单保证任意场景的结果。

把本章的对象替换成语言模型：

| 环节 | 打印任务 | 下一个 Token 预测 |
| --- | --- | --- |
| 输入 | 页数特征 | 前缀的向量表示 |
| 输出 | 一个费用数值 | 每个词表项的分数 |
| 目标 | 实际费用 | 后续 Token 的编号 |
| 本书采用的损失 | 均方误差 | 交叉熵 |
| 更新方式 | 求损失对 w、b 的梯度 | 求损失对网络参数的梯度 |

这里有一个不能照搬的地方：Token 编号只是类别标识。编号 4 比编号 2 大，不意味着预测 3 就“距离正确答案更近”。因此我们把它作为分类问题，评价分给目标类别的概率。[第 05 章](05-模型怎样从文本中学习.md)会实际算出 `-log(目标概率)` 及其梯度。

## 8. 让打印店开张：完整程序就在这里

把下面整段保存成 `main.py`，执行 `python3 main.py`。程序会先复现前面的账单、损失和学习率实验，再让三张订单共同训练 200 步，只用 Python 标准库。

代码看起来比一张小票长，读起来可以分三段：`predict` 算费用，`update` 算梯度并更新，`train` 把更新重复做下去。中间的 `demonstrate` 负责把手算案例逐一打印出来，方便查账。

```python
from math import isclose


def predict(x, w, b):
    return w * x + b


def mean_squared_error(samples, w, b):
    return sum((predict(x, w, b) - y) ** 2 for x, y in samples) / len(samples)


def update(samples, w, b, learning_rate):
    # 所有误差和梯度都基于同一组旧参数，最后一起更新。
    errors = [predict(x, w, b) - y for x, y in samples]
    gw = sum(2 * e * x for (x, _), e in zip(samples, errors)) / len(samples)
    gb = sum(2 * e for e in errors) / len(samples)
    return w - learning_rate * gw, b - learning_rate * gb


def demonstrate():
    orders = [(1.0, 2.0), (2.0, 4.0), (3.0, 6.0)]
    print("第 2 节：比较两套估价规则")
    for name, w, b in [("A", 1.0, 0.0), ("B", 1.0, 2.0)]:
        errors = [predict(x, w, b) - y for x, y in orders]
        loss = mean_squared_error(orders, w, b)
        print(f"模型 {name}：误差和={sum(errors):.1f}，均方误差={loss:.6f}")
    assert isclose(mean_squared_error(orders, 1, 0), 14 / 3)
    assert isclose(mean_squared_error(orders, 1, 2), 2 / 3)

    print("\n第 3 节：固定 b=0，轻轻改变 w")
    for w in [0.99, 1.0, 1.01]:
        print(f"w={w:.2f}，预测={predict(2, w, 0):.2f}，损失={(predict(2, w, 0)-4)**2:.4f}")
    approximate_gradient = ((2 * 1.01 - 4) ** 2 - 4) / 0.01
    assert isclose(approximate_gradient, -7.96)
    print(f"向前试探得到的变化率约为 {approximate_gradient:.2f}，精确导数为 -8")

    print("\n第 4 节：每次都从 w=1、b=0 出发，更新一次")
    single_order = [(2.0, 4.0)]
    for rate, expected_loss in [(0.01, 3.24), (0.1, 0.0), (0.3, 16.0)]:
        w, b = update(single_order, 1.0, 0.0, rate)
        loss = mean_squared_error(single_order, w, b)
        print(f"学习率={rate:.2f}，w={w:.2f}，b={b:.2f}，预测={predict(2,w,b):.2f}，损失={loss:.2f}")
        assert isclose(loss, expected_loss, abs_tol=1e-12)
    w, b = update(single_order, 1.0, 0.0, 0.3)
    w, b = update(single_order, w, b, 0.3)
    print(f"学习率 0.30 再更新一次：预测={predict(2,w,b):.1f}，损失={mean_squared_error(single_order,w,b):.1f}")
    assert isclose(predict(2, w, b), -4.0)
    assert isclose(mean_squared_error(single_order, w, b), 64.0)

    w, b = update(single_order, 1.0, 0.0, 0.1)
    print("单张订单学对后，检查其他页数：")
    for x in [1, 2, 3, 4]:
        print(f"页数={x}，预测={predict(x,w,b):.1f}，目标={2*x}")

    print("\n第 5 节：黑白和彩色订单，使用独立的一组价格")
    inputs = [[2, 3], [1, 4]]
    weights, bias = [0.5, 1.0], 0.2
    predictions = [sum(x * w for x, w in zip(row, weights)) + bias for row in inputs]
    print(f"两张订单的预测费用：{predictions}")
    assert all(isclose(actual, expected) for actual, expected in zip(predictions, [4.2, 4.7]))

    print("\n第 6 节：阶梯优惠，费用 = 2x - ReLU(x-2)")
    for x, expected in [(1, 2), (2, 4), (3, 5), (4, 6)]:
        relu = max(0, x - 2)
        fee = 2 * x - relu
        print(f"页数={x}，ReLU(x-2)={relu}，费用={fee}")
        assert fee == expected
    print("\n固定教学案例核对通过。下面开始可修改的训练实验。")


def train(samples, learning_rate, steps):
    w, b = 1.0, 0.0
    print(f"\n共同训练：样本={samples}，学习率={learning_rate}，更新次数={steps}")
    for step in range(steps + 1):
        loss = mean_squared_error(samples, w, b)
        if step % 50 == 0 or step == steps:
            print(f"step={step:3d}，loss={loss:.6f}，w={w:.4f}，b={b:.4f}")
        if step < steps:
            w, b = update(samples, w, b, learning_rate)
    print("训练后逐单检查：")
    for x, y in samples:
        print(f"页数={x:g}，预测={predict(x,w,b):.4f}，目标={y:g}")
    # 改成阶梯优惠实验时，x=4 已包含在训练集中，目标也不再是 8。
    print(f"额外查询 x=4：预测={predict(4,w,b):.4f}（是否见过、目标多少，请按实验数据判断）")


if __name__ == "__main__":
    demonstrate()

    # 第 8 节的三项实验从这里修改，每次只改变一个条件。
    samples = [(1.0, 2.0), (2.0, 4.0), (3.0, 6.0)]
    learning_rate = 0.05
    steps = 200
    train(samples, learning_rate, steps)
```

默认训练最后一行应接近：

```text
step=200，loss=0.000155，w=1.9856，b=0.0328
```

这时查询 4 页，预测约为 7.9751 元，已经靠近规则给出的 8 元。参数还没有恰好等于 `(2,0)`，所以尾数有一点偏差。

接下来只改末尾的一项设置。先写预测，再运行，别让实验变成“所有旋钮拧一遍，然后猜哪个有用”：

| 改动 | 先预测 | 应该解释的结果 |
| --- | --- | --- |
| 学习率从 0.05 降到 0.005 | 相同 200 步会学得更快吗？ | 在这组初值和数据上，小步幅进展更慢；步子小不等于有限步数内更好 |
| 样本只留 `(2,4)` | 训练损失趋近 0 后，4 页一定为 8 吗？ | 不一定；一个方程不能确定两个参数 |
| 样本改成 `(1,2),(2,4),(3,5),(4,6)` | 一条直线能把它们全算对吗？ | 不能；这里首先受模型表达形式限制 |

程序里的 `assert` 是对固定手算结果的检查。它们通过，说明这几笔账算对了；换了数据后能不能学好，还要看新的损失、逐条预测和未见输入。盖过章的旧账单，不能替新业务担保。

## 9. 自测与解答

**题一：** `x=3、w=2、b=1、y=6`，预测、误差和平方损失各是多少？

**解答：** 预测 7，误差 1，损失 1。这里误差的正号表示多估。

**题二：** 两张订单分别多估 2 元、少估 2 元，均方误差为 0 吗？

**解答：** 为 `(2²+(-2)²)/2=4`。为 0 的是有符号误差的平均，二者评价不同。

**题三：** w 的梯度为 −8，学习率 0.01，旧 w=1，更新后是多少？如果写成 `w+学习率×梯度` 会怎样？

**解答：** 正确结果 `1.08`。写成加号会得到 `0.92`，在本题当前位置向损失上升的方向移动。

**题四：** `X` 有 7 行、每行 4 个特征，希望每行输出 6 个分数，W 形状是多少？

**解答：** `(4,6)`，输出为 `(7,6)`。第 04 章的语言模型输出层就是这种“表示宽度 → 词表大小”的映射。

**题五：** 为什么同时调整 w、b 时，不能改完 w 再重新计算 b 的梯度，并仍声称使用了原先那组梯度？

**解答：** 新 w 改变了预测和误差，b 的梯度也会随之变化。两个梯度此时来自不同参数点。那可以形成另一种更新过程，但不是本章手算的一步。

**题六：** 提示词从“续写”改成“翻译”，模型输出改变。这与打印任务的哪种变化更相似？

**解答：** 参数保持不变而输入变化。不能只从输出变化推断它训练了，也不能把对话中的“纠正一次”直接等同于梯度更新。
