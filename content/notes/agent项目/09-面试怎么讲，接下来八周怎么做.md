# 面试怎么讲，接下来八周怎么做

先把项目解决的问题讲清楚，再挑一两个已经做过的实验展开。框架名称可以晚一点说，面试官通常更想知道你负责什么、为什么这样设计、结果怎么证明。

## 三分钟介绍

下面是一份讲述参考。按你实际做过的内容调整，不把设计方案说成公司已上线功能。

“我做的是预算汇报 Agent。员工想比较几个项目的预算和费用，原来要自己选口径、查汇总、找明细，再整理 Excel。我希望他用一句话说明需求，系统补齐关键条件后，把查询和交付接起来。

技术上采用 Java 21。计划中的业务入口是 Spring Boot，执行编排用 LangGraph4j。模型负责理解和选择允许的下一步，Java 服务负责权限、分摊与查数。缺预算版本时图暂停，用户回答后继续原任务；等待期间不占着数据库事务。

这里最容易出问题的是数字口径。比如 P01 预算 70 万，连上两条费用明细后会被加成 140 万。我先统一聚合粒度，再固定一次任务的数据和规则版本。所有图表与导出都应该引用已经冻结的查询结果。

目前有可运行的 Java 演示，32 项 JUnit 检查通过。我还用三个独立 JVM 验证了恢复：第一次等待口径，第二次提交导出任务后模拟返回丢失，第三次恢复，数据库仍只有一条任务。操作编号在调用前保存，数据库唯一约束负责去重。

现阶段验证的是合成数据下的计算、图恢复和任务受理。真实模型、生产权限以及 Excel 文件生成还没接齐，后续会按这些边界补集成测试。”

## 面试官感兴趣，再往下讲

| 对方追问 | 用什么材料展开 |
| --- | --- |
| 这为什么需要 Agent？ | 用户缺信息时追问、根据差异决定下钻，固定计算继续用业务代码 |
| 为什么选 LangGraph4j？ | 状态、条件边、断点与检查点，现有 Java 服务可以直接复用 |
| 金额怎样保证正确？ | 手算 52 万与 56 万，解释聚合粒度、尾差和分摊轴 |
| 重启之后怎么继续？ | 同一个 threadId、更新状态、resume、重新读取最新检查点 |
| 重试怎么不重复？ | 稳定 operation_id、唯一约束、参数哈希、执行代次 |
| 做到什么程度？ | 源码、32 项测试与三进程日志，以及明确未接入的部分 |

不要把所有回答背成一样长。对方问一个具体点，先答机制，再拿一条运行结果支持；如果还要追问，再打开代码。

## 五分钟演示怎么安排

先花一分钟讲业务输入和正确金额。运行测试后，不必逐条解释 32 个名字，挑“连接放大”和“响应丢失”两个最容易看懂的案例。

再执行三条命令，观察下一节点从 `await_basis` 到 `submit_export`，最后 `__END__`。给面试官看导出任务数一直没有超过 1，并打开唯一约束与操作编号生成位置。最后说明 `END` 在这个演示里代表任务受理完成，尚未代表 Excel 可下载。

## 简历可以写到什么程度

可以写：“基于 Java 21 与 LangGraph4j 1.8.27 实现预算分析演示，支持缺失口径暂停、检查点恢复及条件下钻；使用稳定操作编号与数据库唯一约束处理导出重试，通过 32 项 JUnit 检查及跨 JVM 恢复验证。”

不要加未经测量的提效比例、生产并发量或模型准确率。面试时源码和日志能支持到哪里，简历就写到哪里。

## 接下来八周，按可验收结果推进

| 周次 | 要做的事 | 这一周结束时拿什么验收 |
| --- | --- | --- |
| 1 | 固定业务样本、指标与比较政策，复核现有 Java 计算 | 人工金额答案、边界样本与全部计算测试 |
| 2 | 接 Spring Boot 的任务与状态接口，加入真实登录主体 | 未授权请求被拒，重复提交有确定处理，HTTP 不长期挂起 |
| 3 | 接一个真实模型，替换 NextStepPolicy，约束动作与参数 | 固定问题集能记录正确计划、错误分类与调用成本 |
| 4 | 接查询计划编译与目标数据库 | 正确结果集、负例 SQL、权限隔离与连接池串身份测试 |
| 5 | 接查询结果快照、图表和 Excel | 图表、汇总、分摊明细、清单金额能逐项核对 |
| 6 | 完善持久层、恢复命令去重和任务租约 | 并发回答、重启、超时、旧 Worker 均有故障验证 |
| 7 | 发布 Skill 与资料版本，加入旧任务回归 | 更新功能后既能做新任务，也不破坏已有任务 |
| 8 | 跑完整回归，录制演示，整理真实限制 | 从用户请求到可下载报表的证据，能复述失败与修复过程 |

每周先交付一条能验收的链路，别同时铺开太多框架。当前演示已经覆盖部分第 1、3、6 周的基础机制，但不能因此把这些周对应的生产接入都算完成。
