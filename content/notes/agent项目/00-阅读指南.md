## 面试准备重点

先读架构，再读 Agent 执行机制与工程实现，最后用难点和追问题检验理解。重点包括：

- Agent 的动态决策与固定流程边界，如何依据观察选择下钻并停止。
- 工具粒度、调用 ID 与业务操作 ID、状态合并、上下文失效及 interrupt 重放。
- 查询 DSL 到参数化 SQL 的编译，事实粒度、连接倍增、比率聚合与缺失数据。
- 检查点和外部业务提交之间的故障窗口、幂等事务、Worker 失效与文件发布。
- Agent 评测的分母、追问与拒绝的成功定义、消融实验和性能关键路径。
- 业务 Skill 的发布、依赖与工具权限边界；MCP 和 Function Calling 的适配关系。
- Text-to-SQL 漏掉组织条件时的执行隔离、生成产物权限继承与撤权。
- 标准指标/探索查询双通道，以及 SVG、Excel、查询数据共享结果集的核对机制。

这些内容应当能够支撑“为什么这样做 → 具体怎么做 → 失败如何定位 → 如何验证 → 付出什么代价”的连续追问。

## 事实、假设与完成状态

已知业务背景：原预算核算系统接收外部系统同步、人工文件导入和页面维护的数据，形成指标与报表。原简历技术栈包括 Spring Boot、PostgreSQL、MySQL、Redis 等。

本资料中的 Agent、快照发布、检查点、幂等导出与评测体系均为拟实现的独立实践方案，不能据此声称已在原公司上线。所有部门、金额、负载和故障均为模拟场景；没有实际测得的提升比例、生产规模或业务收益。

当前交付状态：设计与深度面试资料已完成；另附可运行的 Python/SQLite 最小实验，11 项工程不变量检查通过。完整 Java/Agent 应用、真实模型评测、LangGraph 崩溃恢复与性能实验尚未实施。局部实验不能作为完整系统已上线的证明。

## 范围选择

目标版本做：单 Agent、业务可维护的两个 Skill、Java MCP 能力包装、标准指标与受限 Text-to-SQL 双通道、全链路权限、数据版本与幂等任务，以及 SVG/Excel/原查询数据的统一交付。

实施分阶段：先用受控指标工具跑通任务与结果集，再补 Skills/MCP 管理、探索 SQL 和多格式产物。业务说明 RAG、多副本执行、复杂共享和更多图表类型按时间后置。阶段性未实现必须明确标注，不能把全套目标当成八周内保证完成的功能。

暂不做：通用多 Agent 平台、预算自动修改、付款操作、模型训练、复杂可视化编排器。

准备目标是能够解释每一条关键执行路径，复现典型失败，并用证据说明修复为何有效。
