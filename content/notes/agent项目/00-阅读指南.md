# 预算分析与导出 Agent：面试准备资料

这套资料面向有七年 Java 开发经验、计划在两个月内求职的开发者。项目从预算核算系统的多来源数据、指标报表与导出场景出发，设计一个能够理解需求、受控查数、下钻分析和导出结果的 Agent。

## 阅读顺序

1. [项目背景与整体架构](01-项目背景与整体架构.md)：业务目标、职责边界、组件选择与完整请求链路。
2. [Agent 设计与执行流程](02-Agent设计与执行流程.md)：状态、工具、路由、上下文与恢复。
3. [技术实现与工程边界](03-技术实现与工程边界.md)：指标语义、查询、数据版本、权限、任务与观测。
4. [难点排查与优化实验](04-难点排查与优化实验.md)：三个核心难点、一个性能优化以及可复现的验证方式。
5. [面试讲述与八周实施计划](05-面试讲述与实施计划.md)：三分钟介绍、深入追问、实施里程碑与证据模板。

## 事实、假设与完成状态

已知业务背景：原预算核算系统接收外部系统同步、人工文件导入和页面维护的数据，形成指标与报表。原简历技术栈包括 Spring Boot、PostgreSQL、MySQL、Redis 等。

本资料中的 Agent、快照发布、检查点、幂等导出与评测体系均为拟实现的独立实践方案，不能据此声称已在原公司上线。所有部门、金额、负载和故障均为模拟场景；没有实际测得的提升比例、生产规模或业务收益。

当前交付状态是“设计文档完成”，业务代码、故障注入与性能实验尚未实施。完成实验后，将结果、日志、代码提交和环境信息补入对应章节。

独立项目使用合成数据。公开材料不包含公司内部记录、真实财务金额、接口地址或代码。

## 范围选择

第一版做：一个单 Agent、预算执行分析、指标口径确认、三到五类查询/导出工具、数据版本绑定、幂等导出与基础评测。

第二阶段选做：带来源的业务说明检索、受限 Text-to-SQL、数据来源核查。三者按时间选择，不作为第一版前置依赖。

暂不做：通用多 Agent 平台、预算自动修改、付款操作、模型训练、复杂可视化编排器。

准备目标是能够解释每一条关键执行路径，复现典型失败，并用证据说明修复为何有效。
