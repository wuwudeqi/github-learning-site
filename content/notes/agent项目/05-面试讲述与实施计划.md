# 面试讲述与八周实施计划

## 1. 三分钟介绍结构

先背景约 30 秒，再架构约 45 秒，Agent 流程约 45 秒，核心难点约 45 秒，实际完成情况约 15 秒。时间仅作练习参考，不必机械计时。

### 当前设计阶段的讲述示例

“我过去的工作涉及企业预算核算和报表系统，数据来自系统同步、文件导入以及页面维护。在这个业务背景上，我正在设计一个独立的预算分析与导出 Agent，使用模拟数据，目标是完成自然语言查数、口径确认、差异下钻和导出。

架构上保留 Spring Boot 预算应用负责鉴权、指标查询、计算与导出，独立的 Python/LangGraph 服务负责多步分析和暂停恢复。Java 短时提交任务后返回 ID，模型在后台运行；Agent 调用 Java 业务工具。分析状态由 Python 管理，导出状态由 Java 管理，不跨模型调用持有数据库事务。

例如用户要求分析上半年预算执行，Agent 会先确认预算和实际的口径，生成查询计划，绑定数据版本，再查询和下钻。结果引用工具证据，导出交给后台任务。

我计划重点验证三个问题：指标口径理解错误、多步查询期间的数据变化、工具超时后的重复执行。分别通过指标目录与校验、分析版本绑定以及业务幂等处理。目前设计已完成，代码与实验正在按计划推进。”

实现完成后按实际状态改成过去时，加入最扎实的一项实验结果。不要把独立项目说成公司生产上线，也不需要主动讲与项目无关的简历历史。

## 2. 深入展开顺序

先画架构和一次请求链路，再讲 Agent 状态、路由与工具契约。面试官追问时进入指标、版本或任务实现，最后用对应失败轨迹和验证结果支撑。避免一开始列框架名或连续讲四个事故。

## 3. 高频追问与回答要点

| 问题 | 回答要点 |
| --- | --- |
| 为什么需要 Agent，固定报表不行吗？ | 固定报表继续使用；Agent 处理自然表达、条件补全与动态下钻，不替代确定性计算。 |
| 这到底是工作流还是 Agent？ | 确定性状态图中包含模型的理解与下钻决策，清楚说明自主范围。 |
| 为什么 LangGraph？ | 需要显式状态、分支、暂停和恢复；代价是图与状态维护，简单单轮查询不一定需要。 |
| Java → Python → Java 是否绕？ | 提交分析与业务工具执行是不同接口。提交持久化后就返回，工具不反向调用 Agent；复用原有预算规则并隔离长任务，但承担双服务成本。 |
| 谁管理任务状态？ | Python 管分析运行，Java 管请求归属和导出任务。检查点不替代持久化受理、Worker 认领与业务幂等。 |
| 为什么不用多 Agent？ | 同一数据域与权限边界下没有必要，并行查询由程序完成。 |
| 工具是谁执行的？ | 模型输出调用请求，应用验证并执行，结果回到编排流程。 |
| 结构化输出是否解决幻觉？ | 只解决部分结构问题，指标含义、权限和数值还需验证。 |
| 为什么 RAG 不能直接查金额？ | 金额需要精确过滤聚合与版本一致性；RAG 用于定义和说明。 |
| 检查点是否保证只执行一次？ | 不保证跨系统业务副作用只发生一次，需稳定操作 ID 和后端幂等。 |
| 预算执行率怎么处理零预算？ | 返回无定义状态和说明，不虚构百分比；正负数及冲销有业务规则。 |
| 快照是否等于实时一致？ | 只固定分析输入，来源新鲜度仍需检查并展示。 |
| 怎样证明效果？ | 固定案例、基线、留出测试、分层错误、故障注入和相同环境对比。 |
| 为什么不只用提示词限制权限？ | 权限属于可信代码和数据访问层，模型输入不能更改授权。 |
| 用户要求忽略规则怎么办？ | 工具权限照常生效，未授权对象不可访问；不能依靠模型自觉。 |
| SSE 断开后任务怎么办？ | 网络连接与业务任务分开；支持查询与重连，显式取消单独处理。 |
| 哪部分最体现 Java 经验？ | 精确计算、数据库版本、异步任务、幂等、租约、权限与排查链路。 |

回答从做过的实现出发。未实现功能说“设计选项/后续验证”，不把了解过等同于生产经验。

## 4. 八周实施安排

| 周 | 项目产出 | 面试准备 |
| --- | --- | --- |
| 第 1 周 | 合成数据、指标定义、基础查询和 API 契约 | 梳理真实工作贡献，收集 JD，开始试投 |
| 第 2 周 | SDK 工具循环、持久化任务受理、简单端到端查询 | 能解释模型/应用/工具职责 |
| 第 3 周 | LangGraph 状态、追问、计划校验、工具错误策略 | 架构图与三分钟介绍 |
| 第 4 周 | 报表版本、数据更新实验 | 深挖 SQL、事务与数据一致性 |
| 第 5 周 | 异步导出、幂等、持久化恢复与故障注入 | 任务状态和恢复追问 |
| 第 6 周 | 评测集、trace、按瓶颈优化 | 补实验结果，更新项目简历 |
| 第 7 周 | 集成演示与回归，修复面试暴露的问题 | 模拟面试、持续投递与复盘 |
| 第 8 周 | 稳定演示与证据整理，停止扩展范围 | 集中推进面试与机会 |

按可用时间调整，不承诺固定周数一定完成。投递与学习并行。时间不足先保留固定工具查数、口径校验、幂等导出与评测；Text-to-SQL、RAG 和来源追溯可后置。

## 5. 完成标准

- [ ] 新环境按照说明可以启动；模型、依赖和数据版本可追溯。
- [ ] 一次预算查询能完成条件确认、计算、引用和导出。
- [ ] 无权限、缺数据、零预算、错误参数有明确行为。
- [ ] 三个难点至少各有一个稳定复现与修复验证。
- [ ] 有固定测试集及没有用于调参的留出案例。
- [ ] 提交真实 trace、结果和限制，没有凭空填写提升比例。
- [ ] 能解释一次失败从模型到 SQL/任务层的定位路径。

## 6. 简历描述模板

完成后按实际删改：

“预算分析与导出 Agent（独立实践）：基于 Python/LangGraph 与 Spring Boot，构建自然语言查询、指标口径确认、差异下钻和异步导出流程；通过结构化查询计划与后端校验控制指标选择，以报表版本绑定保障多步查询一致性，以操作幂等和持久化任务处理超时恢复；使用合成数据和固定案例验证查询正确性与故障处理。”
