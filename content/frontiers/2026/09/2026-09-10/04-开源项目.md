## 01 · TeamAI：共享团队技能与规则

**近期维护｜最新发行记录为 9 月 9 日 v0.24.0-beta.3，预发布。**

TeamAI 将团队的技能、规则、文档和工具配置放进共享 Git 仓库，再同步到不同 Agent 客户端。适合多人维护相同项目时减少配置分散，也让经验更新可以经过分支与审阅流程。知识召回和团队改进功能仍标为 beta，支持范围应按具体客户端的矩阵检查。

最小路径是准备一个团队仓库，安装 `npm install -g teamai-cli`，在试验项目运行 `teamai init <仓库地址>`。它依赖 Node/npm、Git 和仓库访问权，也会安装或更新客户端侧资源；建议先读同步范围，再决定项目级还是用户级。共享配置中不要混入个人凭据，团队成员还需要各自可用的模型服务。本期读到了完整许可正文，确认并无超出 MIT 的额外限制。

[项目](https://github.com/Tencent/teamai-cli) · [MIT](https://github.com/Tencent/teamai-cli/blob/main/LICENSE)

## 02 · Diagram Design：生成可编辑的解释图

**近期维护｜README 当前列出 39 类图解。**

这是带公开模板和导出流程的 Agent 技能，用于把系统结构、事件顺序、状态变化或依赖关系表达成图。产物为独立 HTML 与 SVG，可以继续修改并放进文档。静态输出是默认方式，可选动画用来逐步解释，不是必须依赖在线设计服务。

最小上手不必先连接模型：下载仓库，打开 `skills/diagram-design/assets/index.html` 查看样式，再按 README 选择对应客户端的插件安装方式。生成内容需要兼容的 Agent；导出位图还可能需要 Playwright 和浏览器。模板能提供一致布局，无法替作者保证箭头方向和概念关系正确。适合先用一个已有流程图比较表达是否更清楚，而不是一开始批量替换全部文档。

[项目](https://github.com/cathrynlavery/diagram-design) · [MIT](https://github.com/cathrynlavery/diagram-design/blob/main/LICENSE)

## 03 · PI-Desktop：本地项目的 Agent 工作台

**近期候选版｜9 月 9 日 v0.14.6-rc.4，不是稳定版标记。**

PI-Desktop 把项目、会话、模型与工具放在独立桌面界面里，可查看命令输出、审阅差异并管理长会话。它适合希望切换模型供应商，同时保留本地项目工作方式的开发者。仓库强调本地优先，但这不表示远程模型调用也留在本机。

可先从发行页选择与系统匹配的安装包，按文档配置模型供应商，再打开一个可以安全试验的项目。若从源码构建，需要 Node.js 至少 22.19、pnpm 至少 10 和 Rust 工具链；仓库当前实际固定的版本还应一起检查。开源客户端与模型服务分开计费，预发布版本也需评估会话兼容性。最有价值的试用是完整走过一次计划、修改、查看差异和撤销，而不是只确认聊天能发送。

[项目](https://github.com/vastsa/PI-Desktop) · [LGPL-3.0](https://github.com/vastsa/PI-Desktop/blob/main/LICENSE)

## 04 · Docling：把复杂文档转成结构化材料

**成熟工具｜核验发行 v2.126.0，9 月 4 日。**

Docling 解析 PDF 等文档，保留版面、表格等结构，并可导出便于后续检索或整理的材料。适合为资料库建立统一入口，特别是不能简单复制文本的复杂文件。它负责转换环节，引用是否准确仍要回到原文页面核对。

最小路径是在 Python 3.10 以上的隔离环境安装 `pip install docling`，再用 CLI 转换一份自己的小文档。可以先抽查标题顺序、双栏阅读顺序与一张复杂表格，再扩大处理量。选择视觉模型管线时，还会增加模型下载、运行资源和对应许可条件。代码采用 MIT，具体模型各有许可，二者不能混用；部署时还应记录所用模型与参数，避免同一份材料在不同配置下得到难以解释的结果。

[项目](https://github.com/docling-project/docling) · [MIT](https://github.com/docling-project/docling/blob/main/LICENSE)

## 05 · Crawl4AI：把网页整理成可用文本

**成熟工具｜核验发行 v0.9.3，8 月 31 日。**

Crawl4AI 提供基于浏览器的异步网页采集与转换，适合把页面整理为后续模型可处理的文本或结构化结果。它可以作为公开资料收集的一个环节，但页面成功打开、正文成功提取和信息完整是三件事，不能只检查请求是否返回成功。

最小路径是安装 `pip install crawl4ai`，运行 `crawl4ai-setup` 准备浏览器，再按 README 的异步示例处理一个允许访问的页面。它依赖浏览器运行环境；使用模型提取时还需相应服务或本地模型。建议把 URL、抓取时间和原始材料一并保留，遇到登录、反爬或异常结构时明确记录失败。浏览器工具不会自动补全缺失正文，也不会替内容编辑判断来源是否可靠。

[项目](https://github.com/unclecode/crawl4ai) · [Apache-2.0](https://github.com/unclecode/crawl4ai/blob/main/LICENSE)

## 06 · LangExtract：抽取结果附带原文位置

**成熟工具｜核验发行 v1.6.0，7 月 2 日；9 月仍有仓库维护。**

LangExtract 用模型把非结构化文本整理为字段，同时保留结果在原文中的位置，便于人工检查抽取依据。它适合从公告、合同草稿或研究材料中收集人物、事件和关系，尤其适合需要回答“这个字段从哪句话来”的工作流。

最小路径是安装 `pip install langextract`，定义抽取任务和一个高质量示例，再对短文本运行官方示例。使用 Gemini 等云模型需要配置 API，选择其他后端也要核对支持方式。原文位置提高可追溯性，并不保证字段含义正确；应检查跨句关系、同名实体和遗漏项目。长文档分段也可能拆散上下文，因此建议保留原文及样本答案，让人工抽查能持续进行。

[项目](https://github.com/google/langextract) · [Apache-2.0](https://github.com/google/langextract/blob/main/LICENSE)

## 07 · Pydantic AI：为模型输出建立类型接口

**近期更新｜v2.42.0，9 月 9 日。**

Pydantic AI 为 Python 应用提供模型、工具、依赖与结构化输出的接口。最新版本加入 GitHub Copilot Provider，并收紧延迟工具批准结果的无效值处理。对已有 Python 代码的团队，价值在于让模型结果进入可检查的数据结构，再交给后续业务函数。

最小路径是从官方文档的基础 Agent 示例开始，安装 `pydantic-ai` 并配置所选模型；需要完整文件操作等能力时，按当前文档另看 Harness 组件。建议先定义一个很小的输出结构，验证缺失字段和错误类型怎样处理。类型合法只说明形状符合要求，模型仍可能给出内容错误但结构正确的结果。核心代码、商业观测平台与第三方模型账单属于不同层次，使用时应分别选择。

[项目](https://github.com/pydantic/pydantic-ai) · [官方文档](https://pydantic.dev/docs/ai/) · [MIT](https://github.com/pydantic/pydantic-ai/blob/main/LICENSE)

## 08 · Graphiti：保存随时间变化的关系

**近期维护｜v0.30.2，9 月 8 日 UTC。**

Graphiti 面向时间知识图谱：持续接收文本事件，提取实体关系，并记录信息随时间发生的变化。适合“某人在什么时候负责哪个项目”这类问题，避免把已过期与当前关系不加区分地放在同一个搜索结果里。

最小路径是安装 `graphiti-core`，准备官方支持的图数据库，再运行 quickstart 的添加事件和查询示例。当前文档要求 Python 3.10 以上，可选 Neo4j、FalkorDB 等后端，默认还需要用于抽取和嵌入的模型服务。Kuzu 路径已标记弃用，不能仅凭旧教程选择。图结构不会自动消除模型抽取错误；应保留事件来源、时间和纠错方式。开源库与 Zep 托管服务分开，数据库部署与模型调用也会增加维护成本。

[项目](https://github.com/getzep/graphiti) · [Apache-2.0](https://github.com/getzep/graphiti/blob/main/LICENSE)

## 09 · marimo：让分析笔记按依赖自动更新

**成熟工具｜核验发行 0.24.0，8 月 17 日；仓库持续维护。**

marimo 是响应式 Python notebook，会根据单元之间的依赖决定哪些计算需要更新。笔记保存为 Python 文件，便于版本管理，也能作为脚本或应用运行。它适合模型评估、数据探索和向同事展示可以调整参数的分析过程。

最小路径是安装 `pip install marimo`，运行 `marimo tutorial intro`，再用 `marimo edit` 新建笔记。需要更多 SQL 或 AI 辅助能力时可选择额外依赖，而不必一开始全部启用。响应式执行减少部分隐藏状态问题，但不会修复数据泄漏、错误指标或不可复现的外部 API。分享之前仍应固定依赖、记录数据版本，并确认从头执行也能得到相同结论；可交互并不等于分析已经正确。

[项目](https://github.com/marimo-team/marimo) · [Apache-2.0](https://github.com/marimo-team/marimo/blob/main/LICENSE)

## 10 · Pascal Editor：可连接 Agent 的三维建筑编辑器

**近期维护｜仓库中技能包有新预发布，不将其版本号当编辑器正式版。**

Pascal Editor 是基于 React Three Fiber 与 WebGPU 的三维建筑编辑器，可在浏览器使用，也提供 CLI 和 MCP 接入。适合把空间草图、建筑元素与 Agent 操作结合，让自动生成的变化仍能在可视化场景中检查。它属于创作工具，不是单纯的文生图模型。

最小路径可先查看官方在线编辑器；本地开发则从仓库根目录执行 `bun install` 和 `bun dev`，按 README 打开 3002 端口。需要支持相应图形能力的浏览器，模型侧连接与工具权限要另行设置。仓库最新标签涉及 `pascal-agent-skills`，不能据此判断编辑器全部功能已稳定发布。AI 能改动场景不代表满足结构、安全或施工要求，专业设计仍需对应流程检查。

[项目](https://github.com/pascalorg/editor) · [在线编辑器](https://editor.pascal.app/) · [MIT](https://github.com/pascalorg/editor/blob/main/LICENSE)
