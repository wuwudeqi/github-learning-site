# 前沿日报：启动、恢复与完成

## 每次触发都执行工作

这是每日生成和发布任务。07:30 是主执行时间；08:30、09:30 是同一任务的补漏检查。自动补漏时，当天已核验上线则直接结束，不重写或重复发布；用户明确要求重新生成当天日报时，按新要求更新原期刊及稳定 id，并重新完成发布核验。当日未完成时继续处理，不能以“定时器已启用”结束。

在仓库根目录工作。第一步按 Asia/Shanghai 确定日期，读取 `.frontiers/current.json`。若文件为当日未完成状态，恢复其中的阶段、来源文件和下一步；否则创建当日进度。人工指定补跑日期时遵循用户指定日期。

进度使用 JSON，至少包含 `issueDate`、`status`、`stage`、`updatedAt`、`nextAction`、`sourceAudit`；发布后补充 `commit`、`deploymentRun`、`publishedUrl`、`verifiedAt`。使用临时文件后重命名更新，避免部分写入。它存于已忽略的 `.frontiers/`，不进入网站。每完成来源覆盖、内容写作、构建、推送、线上核验中的一个阶段都保存一次。

发生上下文压缩或恢复会话时，先读该文件和当日来源审计。当前未完成日期是继续工作的依据；不要回到旧对话重新确认定时配置。每批检索保存有用证据，减少一次性读入历史全文。遵循 `frontiers-editorial.md` 的来源与内容要求。

写作与配图同步推进。先列各模块的关键解释点，严格按“对应来源的有效原图 → imagegen → HTML/JS”选图，逐图保存原图候选与取舍理由。在进度中保留待查找、待制作、已保存及待检查的图片路径；恢复时继续尚未完成的关键图，不把只有总览图的初稿当成图文完成。imagegen 保存最终提示词与采用路径，HTML/JS 保存可复现源码和数据；将实际检查写入当日审计 `visualReview`。这套规则自 2026-09-11 更新后下一次生成起采用，也适用于用户明确要求的同日重做；仅调整定时任务或对已发布日报补漏复核时，不因此触发整期重写。

## 完成条件

1. `npm run check:frontiers -- --date YYYY-MM-DD` 成功。该命令明确要求目标日期的六个文档和审核记录；旧日报通过不能替代今天。
2. `npm run build` 成功，仅提交本任务文件并推送。保存提交号。
3. 对应 GitHub Actions 成功。保存运行链接/编号。
4. `node scripts/verify-frontiers-published.mjs --date YYYY-MM-DD` 成功。它核对线上目录与本地当期六个文档、图片/代码附件的内容摘要。网络失败保持未完成，不能跳过或猜测成功。
5. 上述均成功才将状态写为 `published`，保存核验时间和阅读链接，并通知用户。补漏触发再次核验后安静结束。

若遇到实际错误，保存失败阶段、错误和下一步，报告实际问题。08:30 是目标而非停止条件，超过时间仍完成可靠内容。不要生成空壳、改日期冒充新日报或放宽事实检查。
